#+title: Loom Playground
#+author: Sushil Chhetri

The playground is a scratch space for experimenting with the Loom framework interactively, in the browser. It has no production requirements — break things freely. Use it to prototype flows, test projection logic, try blueprint layouts, and debug a suspend/resume cycle with zero infrastructure.

It is wired with the current architecture: a single [[file:../../docs/architecture.md][~defineConfig~]] composition root, in-memory storage, capability + intent routing, telemetry adapters, and a React UI with Blueprint / Event Log / Projection / Trace / A2UI tabs. All state is folded from the durable event log.

* What it is for

| Scenario                         | How                                                              |
|----------------------------------+-----------------------------------------------------------------|
| Try a builder API                | Wire ~step$~ + ~handler$~ into a flow and call ~ctx.run~         |
| Test a projection shape          | Register a ~projection$~, emit events, watch the Projection tab  |
| Preview a blueprint layout       | Edit ~src/blueprint.ts~ and see it render                       |
| Debug a suspend/resume cycle     | Drive the full lifecycle in-browser (approval gate → resume)    |
| Watch the event log live         | The Event Log tab streams every ~EventEnvelope~ as it commits    |
| Inspect a run's trace            | The Trace tab shows the telemetry (flow + per-step timings)      |

* Running

From the repo root:

#+begin_src bash
pnpm build                              # build framework packages once (fresh clone)
pnpm --filter @loom/playground dev      # start the Vite dev server (HMR)
#+end_src

Open http://localhost:5173 (or whichever port Vite picks).

* How it is wired (the current pattern)

The composition root is one ~defineConfig~ call — no hand-built ~WorkflowRuntime~, stores, or ~onEvent~ wiring. See ~src/main.tsx~:

#+begin_src typescript
import { defineConfig } from "@loom/app";
import { InMemoryProjectionRuntime } from "@loom/projection-runtime";
import { ConsoleTelemetryAdapter } from "@loom/telemetry";

// A projection runtime that also folds a domain projection; defineConfig registers
// the A2UI "ui" surface and wires onEvent → handleEvent for you.
const projectionRuntime = new InMemoryProjectionRuntime();
projectionRuntime.register(TaskProjection);

const app = defineConfig({
  storage: { kind: "memory" },          // no server, no DB
  projectionRuntime,
  surfaces: ["ui"],                      // the A2UI surface ctx.ui.* targets
  catalog,                              // registers the flow as a capability
  observability: { telemetry: [ConsoleTelemetryAdapter, ReactAdapter] },
});

// → app.runtime · app.effectRuntime · app.projectionRuntime · app.bus · app.stores
const handle = await app.runtime.start(RegisteredTaskFlow, input);
const state  = await handle.waitForCompletion();
#+end_src

To persist instead (so the ~loom~ CLI can inspect the log), swap one line:
~storage: { kind: "sqlite", dir: ".loom" }~ — then ~loom logs/debug/inspect --db .loom/events.db <id>~.

* A minimal flow (deterministic)

#+begin_src typescript
import { flow$, step$, handler$ } from "@loom/core";
import type { RegisteredFlow, FlowRunner } from "@loom/workflow-runtime";
import { z } from "zod";

const GreetStep = step$({
  id: "greet",
  inputSchema: z.object({ name: z.string() }),
  outputSchema: z.object({ message: z.string() }),
  // Keep handlers deterministic — no Date.now()/Math.random() in replayable code.
  handler: handler$(async (input: { name: string }) => ({ message: `Hello, ${input.name}!` })),
});

const runner: FlowRunner<{ name: string }, { message: string }> = (ctx, input) =>
  ctx.run(GreetStep, input);

export const HelloFlow = {
  definition: flow$({
    id: "hello-flow", name: "Hello Flow", version: "1.0.0",
    inputSchema: z.object({ name: z.string() }),
    outputSchema: z.object({ message: z.string() }),
    steps: [GreetStep],
  }),
  runner,
} as RegisteredFlow;

// then: defineConfig({ storage: { kind: "memory" }, flows: [HelloFlow] })
#+end_src

* Available packages

| Package                | Use for                                                            |
|------------------------+-------------------------------------------------------------------|
| ~@loom/app~            | ~defineConfig~ — the composition root                             |
| ~@loom/core~           | Builders: ~flow$~, ~step$~, ~handler$~, ~projection$~, ~blueprint$~ |
| ~@loom/projection-runtime~ | ~InMemoryProjectionRuntime~ + custom projections               |
| ~@loom/plugin-renderer-react~ | ~BlueprintRenderer~, ~LoomProvider~, ~useLoom~, ~useProjection~   |
| ~@loom/capability~ / ~@loom/intent~ | Expose a flow as a capability + route a goal to it   |
| ~@loom/telemetry~      | Telemetry adapters (Console + a custom React adapter)             |

Need another package? Add it to ~package.json~ and run ~pnpm install~ from the repo root.

* Tips

- *Keep it messy.* Stub schemas with ~z.any()~, hardcode inputs, log freely.
- *Determinism.* Put anything non-deterministic (clocks, randomness, I/O) inside a ~handler$~/effect (its result is logged) — never in the runner's control flow, or replay/resume diverges.
- *Copy from an example.* The example apps live in the sibling [[file:../../docs/examples.md][~loom-examples~]] repo (check it out beside ~loom~). ~loom-starter~ is the canonical new-architecture app (~defineConfig~ + folder convention + middleware + tests + evals); ~cloud-command-center~ has a fuller React flow + custom projections.
- *Check the console.* The Console telemetry adapter prints every flow/step event.

* Promoting work

Once something works here:

1. Move reusable builders/types to the appropriate ~packages/*~.
2. Move flow/projection/blueprint code into an example in the sibling ~loom-examples~ repo — ~loom-starter~ (folder convention) or ~cloud-command-center~; see the [[file:../../docs/examples.md][examples catalogue]].
3. Add tests with [[file:../../docs/user-guide.md][~@loom/testing~]] (~createTestApp~ / ~waitForPhase~).
4. Build from the repo root: ~pnpm build~.
