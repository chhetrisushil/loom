# Loom Capability Maturity

> Generated from `@loom/spec` (`loom kernel-manifest --emit-docs`). Do not edit by hand — it is
> derived from the version constants + capability registry, which are the source of truth.

**Levels:** `L5` ABI guaranteed · `L4` Verified & benchmarked · `L3` Production-ready · `L2` Stable implementation · `L1` Experimental implementation · `L0` Concept accepted

Levels are **evidence-derived, not self-assessed**: `L5` requires a versioned contract pinned
by a conformance test; `L4` requires a committed bench; `L2`/`L3` require a passing test suite.
`spec.test.ts` fails if a capability claims evidence it does not have — so a badge can't rot.

## Notes

- **Tiered Memory** (`L5`): ADR 0090/0091 — `search` is proven portable by FOUR independent implementations of one kit (in-memory IDF, SQLite FTS5, Postgres tsvector, and the 3P loom-plugin-vector's cosine similarity), which is what makes the seam a contract rather than a description of an inverted index. ADR 0091 took the SPI to 2.0.0: entry `id` (REQUIRED to round-trip, so the read-filter-replace fallback has something to match) plus the optional `remove`, because `search` ranks within one key while a document — the unit a corpus is actually edited in — is a subset of it. MAJOR because a backend that decomposes an entry into columns drops a field nobody told it to keep, which is silent in every case that only checks `content`. L3 → L5 once MEMORY_STORE_SPI_VERSION landed: the level bar is a versioned contract pinned by a conformance kit, and this seam is the first whose implementations live OUTSIDE this repo, which is what made an unversioned contract an actual hazard rather than a formality. As with every SPI here, nothing forces the constant to be bumped when the shape changes — the version is a declaration, the kit is the check.
- **Batched Content Resolution** (`L4`): TS-10 (ADR 0062) — the read-side sequel to ADR 0059's putStream. Optional-method + conformance-skip idiom; interactive budget p95 ≤ 150ms for ≤ 50 refs (asserted in batchedResolution.test.ts against an injected-latency backend).
- **Deterministic Simulation Testing** (`L4`): Test/dev-only harness, not a wire contract → cannot be L5; L4 via its append-overhead bench. Production overhead is structurally zero (no runtime package imports it).
- **Per-Tenant Fair Scheduler** (`L4`): Implements the existing Scheduler interface (drops into any consumer); L4 via its Infinity-fast-path bench. Not L5 — the scheduler is ephemeral, not a durable/wire contract.
- **Runtime Verification** (`L4`): No ABI version constant (it is a tool, not a wire contract) → cannot be L5; L4 via its zero-overhead bench.
- **Blueprint Conformance** (`L3`): ADR 0088 (W1a–W1e); ADR 0094 adds the cross-tree half — `preservesNodes` / `blueprintNodeIds`, which report which node ids a structural change DROPPED, the failure a single-tree validator cannot see. Its second consumer is the a2ui bridge's `identityDiff`, and being a real one changed the API: id sets rather than blueprints, because A2UI components are a flat list. Pure functions over JSON-serializable values — no syscall, no event type, KERNEL_ABI/EVENT_SCHEMA untouched (P10). The catalogue vocabulary is the APP's (the ADR 0084 pattern); builtinCatalog is loom's own eight widgets, not a mandate. catalogCoverage is wired into plugins/renderer-react's suite and immediately found the live gap it was written for — WidgetKind declared 8 kinds, defaultRegistry registered 5, and a test ASSERTED the placeholder string, pinning it as intended. The same hole existed twice on the a2ui egress path — the bridge stamped a catalogId it never checked, and callFunction was never compared to the catalogue's declared `functions`; both are now refusals, and `recompose()` finally produces the `updateComponents` message whose payload type shipped with no producer. Also W1d (optional stable `id` on all 8 builders — the derived id re-identifies a node on every prop edit) and W1e (`by` provenance on SurfacePatchPayload + surfaceProvenanceProjection; SURFACE_PATCH is a userspace event so EVENT_SCHEMA is untouched, and the bridge never forwards `by` to a viewer). L2 → L3 once `db-observability` called it: the one example that COMPOSES a blueprint per question, from an agent's widget selection, with nothing looking at the result before a renderer does. It validates clean on all four topics — so the evidence is the negative case, a test that reuses a topic's primary widget as a WHY widget and gets `duplicate-node-id` (ids are derived from content, so the same entry built twice collides on the renderer's key and one silently replaces the other). Without that, a validator wired to nothing looks identical to one that passes. ADR 0095 extends the same surface to the DATA axis: the address freezes a binding's NAME while the projection behind it is unversioned live code, so a declared `version` is compared by `checkVersionPins` and the recorded pin rides in `Blueprint.projectionVersions`, INSIDE the content address. Its second consumer is `ReadModelService.checkPins` — an unversioned extractor is a live defect there, not a hypothetical, and that is the half an example now exercises: `db-observability`'s `PROFILE_MODEL` declares a version, the journaled profile carries `evidenceVersion` beside the `catalogueVersion` it already recorded, and `evidenceDrift` compares a journaled profile against the model running now (deleting the declaration turns the drift into a silent pass and two tests fail). The BLUEPRINT half is deliberately NOT claimed: no example persists a composed blueprint — nothing in loom-examples emits `BLUEPRINT_COMPOSED` — so a recorded pin would protect nothing there, and checking one at composition time would compare a map to itself.
- **Cancellation, Deadlines & Bounded Effects** (`L3`): ADR 0020 — every other K3 enforcement point is ADMISSION CONTROL (it decides whether the next effect runs); K8.4 is the only one that acts inside a call already in flight, which is why it waited on streaming effects and landed only with ADR 0087's series. A5 predicted it could not be middleware (right — middleware sees the effect once, at the end) and proposed an `EffectContext` usage-reporter hook (wrong — both wired providers report usage once, at the end, so such a hook could only fire where metering already reads the number). What ships observes the only thing a stream reports continuously, its own output, and names the estimate AS an estimate in the type, the reason and the default. Not L4: no committed bench — the acceptance criterion is a latency claim (<1s) that no bench pins, and provider forwarding is best-effort anyway (A7), so the honest ceiling is L3 via the cross-seam integration.
- **Compiler** (`L3`): Manifest schema is versioned but not conformance-PINNED like the semver ABIs → L3, not L5.
- **Decision Materialization** (`L3`): Proposed as L4, but has no dedicated bench → evidence-derived L3.
- **Document Corpora** (`L3`): ADR 0091 — the package owns exactly one thing: the mapping from a DOCUMENT (the unit a corpus is edited in) to the PASSAGES it is searched in, so a revision supersedes its predecessor instead of duplicating it. Storage is `MemoryStore`'s, ranking is the backend's, reproducibility is `ctx.decide`'s, safety is ADR 0085's. NOT a seam: there is nothing to plug — an alternative KnowledgeBase would differ only in its manifest layout, and the seam it would need is one layer down. The second consumer (ADR 0083) is db-sentinel, chosen because it is UNLIKE the first: runbook-recall ingests once and asks once, where an append-only corpus and an upsertable one are indistinguishable — which is exactly how the gap this package closes survived ADR 0090.
- **Typed Resume Payloads** (`L3`): ADR 0077 — the shape counterpart to K12.2's identity gate (which authenticates WHO may resume, never WHAT they send). KERNEL_ABI unchanged 1.1.0: no syscall added, and ctx.suspend's type parameter is erased. Opt-in by presence (G2).
- **Child-Workflow Orchestration** (`L2`): Composed from existing primitives — NO new syscall or event type (P10 win; the plan's CHILD_COMPLETED governed event proved unnecessary). L2; single-child and concurrent fan-out both land on the one suspend/resume cycle, and child failure propagates — awaitChild throws (composing up the tree), awaitChildren settles per-child for the parent to weigh.
- **Classification Path Reach (array crossings)** (`L2`): ADR 0076 — closes a SILENT gap: a sensitive() mark inside an array element collected no path, so it was masked nowhere, encrypted nowhere, externalized nowhere. The @loom/verify `classification-reachability` rule now covers only what remains unaddressable (record/union/tuple/intersection).
- **Durable Agent Loop** (`L2`): ADR 0087 — nothing was missing from the kernel; the loop was on the wrong side of it. A step handler receives `StepHandlerContext` (emit, and nothing else), so 40 model calls were ONE frame, approval had to be hoisted out of the agent, and DECISION_RECORDED was hand-emitted in a shape @loom/learning cannot evaluate. Per-turn durability grows the log with conversation length: the two mitigations already ship (ADR 0054 claim-check for bytes, TieredMemory summarization for turns), and the summarize pass is deliberately NOT wired yet because a lossy nondeterministic summary must be journaled to stay replay-safe. Skill selection is likewise left out until it can go through ctx.decide.
- **Effect Mode Boundary (journaled vs ambient)** (`L2`): ADR 0073 — a boundary CHECK at the execute seam, not a journaling mode: KERNEL_ABI stays 1.1.0, no event type, one replay model. The rejected alternative (ambient = 'skip the journal inside an execution') is DE-2's durability class, a second semantic model inside one execution. Enforced by the entry point, not by context contents, so a transient-looking hand-built context cannot spoof it.
- **Execution-Lifecycle Authorization** (`L2`): L2 (tested; opt-in, byte-identical when unwired). Enforced only when a call carries a principal (trust-boundary model) — a boundary check, not a syscall, so no KERNEL_ABI change; adds EXECUTION_DENIED (EVENT_SCHEMA 1.12.0).
- **Live Query** (`L2`): Pure read-model — no syscall, no event type (P10). L2 (tested; not yet wired into a shipped example path).
- **MCP Apps `ui://` Egress** (`L2`): ADR 0072 D4/D5 — egress only; the host role (iframe, CSP, postMessage) is rejected for this repo (D2), and D8 declines to package one as 3P until a real consumer needs it — it implements no seam, and the part that IS Loom-shaped is pin verification, not sandboxing. No per-flow HTML: the rendered UI is a pure function of (pinned template hash, logged structuredContent), and the pin uses the SAME hashResourceBody the ingress side applies, so a plan-time pin equals what a reader recomputes (ADR 0063 D1). Egress redaction is required-by-configuration, never defaulted.
- **MCP Dynamic Dispatch** (`L2`): ADR 0063 — plugin placement per the ADR 0043 litmus (vendor-specific). Canonical hashing lives in @loom/core (one implementation for drift check + registry change detection). MCP_DISPATCHED/MCP_UI_OBSERVED are userspace domain events (fold skips unknown types — no EVENT_SCHEMA bump). ADR 0072 follow-up (plugins/mcp/src/uiDispatch.test.ts): the ingress UI layer was reachable only from McpClient, because every step seam dispatched through the projection that erases `_meta` — asserted now through the EFFECT, which is the level a flow actually traverses.
- **MCP Server** (`L2`): ADR 0072 D7 — the prerequisite the MCP Apps work sits on (loom previously spoke MCP as a client only). The UI extension gives the SERVER no in-band audience signal, so `audienceOf` is deployment-supplied and defaults to "model": absent an explicit boundary, app-only tools stay unreachable rather than silently open.
- **Placement Adapters** (`L2`): SPI is L5, but only local/remote/CloudRun adapters exist; K8s/Lambda/GPU are demand-driven (#72) → the adapter set is L2.
- **Runner-Body Reach Analysis** (`L2`): ADR 0086 — populating FlowSpec.suspends (which had NO producer) proved two suspension-safety checks wrong: the blanket correlationKey error was false (resume routes by executionId, nothing matches on correlationKey) and would have fired on most correct code; the wakeAt check is real only when no TimerStore is wired, since the runtime derives wakeAt from timeout when one is. A check nothing populates is also a check nobody can see is wrong.
- **Saga / Compensation** (`L2`): NO new syscall/event type/fold change (P10 win; the plan's ctx.compensate syscall + COMPENSATION_* events proved unnecessary — compensators run as replay-guarded ctx.run steps). KERNEL_ABI stays 1.1.0. Verified crash-safe by a DST no-double-compensation property.
- **Sandboxed Reshaping Executor** (`L2`): ADR 0064 — engine choice: quickjs-emscripten (capability-EMPTY VM vs @loom/isolate's subtractively-scrubbed child process; the isolation CONTRACT follows IsolatedToolSpec). idempotent:true (pure function of script+input); resource kills are typed so replay never re-burns CPU. Written once, audited once — the security test list is the audit's executable form. ADR 0089 adds an opt-in worker pool (`workers`, off by default): both engines share ONE `evalInFreshRuntime`, so the 0064 security list is parameterized over them rather than copied, and the pool contributes what the in-engine guards structurally cannot — a hard kill for a script that never reaches the interrupt handler (measured: 790ms against a 50ms wall clock, one interrupt callback). Pool evidence: plugins/sandbox/src/workerPool.test.ts.
- **Shard Rebalancing** (`L2`): ADR 0075 — builds on 0074. Minimal-movement is asserted exactly (a naive `bucket % shardCount` moved 80-89% of buckets); reads fall back to the previous plan until a bucket drains.
- **Step Identity & Interpreter Pattern** (`L2`): No kernel changes — a documented contract + compiler lint (tools/compiler loopIdentity.ts, surfaced via @loom/verify's determinism rule) + crash-matrix tests. Dynamic steps are deliberately outside flowContentHash (K11.1 covers the compiled skeleton only).
- **Storage Scale-Out Decorators** (`L2`): ADR 0074 — capability in packages, optimization in plugins. The decorators now have their OWN committed bench (scaleDecorators.bench.ts), which prices one backend round-trip explicitly and appends 512 envelopes across 512 executions concurrently: 14.8x at the default maxBatch 16 and 51x at 64, tracking the round-trips saved (512 -> 32 -> 8) rather than any backend's properties. Its second half is the counterweight and the reason these stay inert unless explicitly composed — over a FREE in-memory store there is nothing to save, so coalescing costs 1.49x and sharding 2.27x. Still L2, and the missing rung is not measurement: the level bar for L3 is an example or integration exercising it, and the bench itself argues against manufacturing one, since every shipped example runs in-memory where wiring these buys nothing. Promote when a deployment path with a real round-trip exists to point at.
- **Tamper-Evident Audit Chain** (`L2`): L2 (stable + tested, incl. a DST crash/recovery integrity property) — not yet wired into a shipped example/defineConfig path, so not L3; no version constant (a composable wrapper, not a wire contract).
- **Typed Failure Channels** (`L2`): NO new syscall — TypedFailure is a userspace throw caught at the execute seam (KERNEL_ABI stays 1.1.0, the saga/ctx.compensate precedent). EVENT_SCHEMA 1.17.0: additive STEP_FAILED {channel, payload}. Undeclared channels keep legacy at-least-once retry semantics (G2).
- **Untrusted-Content Integrity Axis** (`L2`): ADR 0085 — a value wrapper, NOT a fourth schema marker: confidentiality is a property of a field (static, forever), integrity is a property of a value (acquired at runtime from a specific origin), and a marker that guesses reads as coverage. The check is unconditional because a gate defaulting to off protects exactly the apps that never think about it; the opt-in sits on the producer, where tainting changes the output shape. The REFUSAL is structural; the FENCE is a label a model can be talked across — do not sell the second as the first. AMENDED (R2, 2026-08-18): this entry previously said the guard ran inside every `createLlmEffect` — true, and not load-bearing, because `createLlmEffect` had NO production consumer while `AgentRunner` and `ReasoningRuntime` called `provider.complete` directly. The agent path additionally ERASED the evidence (`JSON.stringify` flattened the envelope, so `isTainted` was false downstream and no later guard could recover the origin). Both paths now guard; the erasure is fixed by re-tainting the serialized body.
- **GPU Worker** (`L0`): Concept only — there is NO gpu-worker package. Demand-driven (#72). A hand-assigned 'L1' would be a badge that lies; evidence-derived it is L0.
