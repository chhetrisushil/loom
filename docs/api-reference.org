* Authoring builders — ~@loom/core~
:PROPERTIES:
:CUSTOM_ID: authoring
:END:

Declarative ~$~ builders produce plain, serializable definition objects (each tagged with a ~_tag~). They have no runtime behavior on their own — the runtime interprets them.

*Reserved ~variables~ keys (2.0):* ~_decisions~ (logged ~ctx.decide~ choices, P9), ~_denials~ (capability ~EFFECT_DENIED~ audit, K2), ~_resources~ (metered totals ~{ tokens, costUsd, ms, count, exceeded? }~, K3), ~_blocked~ (behavioral-safety ~SAFETY_BLOCKED~ audit, K6), ~_indoubt~ (parked ~EFFECT_INDOUBT~ deliveries, K9), and ~_shredded~ (crypto-shred ~PAYLOAD_SHREDDED~ tombstones, K10). *Flow-code versioning for in-flight executions (2.0, K11).* Each flow carries a ~flowContentHash~ (structural fingerprint over step bindings + durable policies, emitted by ~@loom/compiler~ and pinned into ~EXECUTION_STARTED~). A resume whose flow code no longer matches the pinned hash throws ~FlowCodeMismatchError~ rather than replaying against drifted code; ~resumeAs~ deliberately migrates such a run — ~"replay-check"~ verifies every recorded step still exists in the new flow (refuses with ~FlowMigrationCheckError~ otherwise), ~"operator-ack"~ vouches without the check. Either way it records a durable, replay-deterministic ~EXECUTION_MIGRATED~ verdict.

~WorkflowRuntime~ is also exported as *~ExecutionRuntime~ (2.0)* — the same class, renamed for the execution-kernel framing.

** ~ExecutionContext~ — the flow API *(2.0; ~WorkflowContext~ is an alias)*

The ~ctx~ handed to every runner. Every call is durable, ordered, and replayable — and is the kernel's *versioned syscall surface* (K1).

#+begin_src typescript
interface ExecutionContext {
  readonly executionId: string;
  readonly workflowId: string;
  execute<TIn, TOut>(task: ExecutableTask<TIn, TOut>, input: TIn): Promise<TOut>;      // (2.0) generalized primitive
  run<TIn, TOut>(step: StepDefinition<TIn, TOut>, input: TIn): Promise<TOut>;          // thin alias; memoized on replay
  decide<T>(id: string, decider: () => T | Promise<T>,
            opts?: { rationale?: unknown; source?: string }): Promise<T>;              // (2.0, P9) log an optimizer choice
  parallel<T extends unknown[]>(
    pairs: { [K in keyof T]: [StepDefinition<unknown, T[K]>, unknown] },
    options?: { limit?: number }
  ): Promise<T>;                                                                       // results ALWAYS in input order
  suspend(config: { on: string; timeout?: number; correlationKey?: string }): Promise<never>;
  sleep(ms: number): Promise<void>;                                                    // (2.0, T1) durable timer
  sleepUntil(wakeAt: number): Promise<void>;                                           // (2.0, T1) wake at absolute ms
  emit(eventType: string, payload: unknown): void;                                     // durable domain event
  stream(eventType: string, delta: string, done?: boolean): void;                      // token streaming
  readonly ui: A2UIEmitter;                                                            // ctx.ui.set/merge/append …
}
#+end_src

*Durable timers (2.0, T1).* ~ctx.sleep~/~ctx.sleepUntil~ suspend the execution with the absolute wake time recorded in the log; a wired ~TimerService~ fires a durable ~TIMER_FIRED~ resume, so a sleep survives restarts and replays deterministically (the scheduled time is in the log — wall-clock drift never enters the fold). Without a timer service the suspension is still durable and resumable by any node. Declare cron-driven starts with ~schedule$~ (see [[#authoring][~@loom/core~ builders]]) and wire both via ~defineConfig({ timers })~.

*Cancellation, deadlines & bounded effects (2.0, K8).* A step's ~timeoutMs~ bounds a single effect; a flow's ~deadlineMs~ (see ~FlowDefinition~) bounds the whole run against the logged ~EXECUTION_STARTED~ timestamp (never reset by recovery). Breach — or ~handle.cancel()~ / ~ExecutionRuntime.cancel()~ — aborts in-flight effects via ~EffectContext.signal~ and records a kernel-driven ~EXECUTION_CANCELLED~.

*The kernel ABI (2.0, K1).* The syscall surface is named and versioned; a conformance test pins it.

** ~@loom/isolate~ — data-plane isolation & brokered egress (K7)

** ~@loom/store-crypto~ — encryption-at-rest & crypto-shredding (K10)

Wraps any ~EventStore~/~SnapshotStore~ to encrypt *marked* payload fields (dot-paths per event type) under a per-subject key on append and decrypt on read (AES-256-GCM; unmarked events stored verbatim — zero overhead). Erasure is by key destruction: ~shredSubject~ destroys the key (irreversible for everything encrypted under it, in events *and* snapshots) and appends a durable ~PAYLOAD_SHREDDED~ tombstone. A later decrypting read of a shredded execution throws ~PayloadShreddedError~ — replay fails *loudly*, never silently diverges. Optional store capabilities (fencing, ~readRange~, ~copyPrefix~) are forwarded, so it composes with K9.4 and ~fork()~.
