* Authoring builders — ~@loom/core~
:PROPERTIES:
:CUSTOM_ID: authoring
:END:

Declarative ~$~ builders produce plain, serializable definition objects (each tagged with a ~_tag~). They have no runtime behavior on their own — the runtime interprets them.

** Builders

#+begin_src typescript

step$<TIn, TOut>(config: StepConfig<TIn, TOut>): StepDefinition<TIn, TOut>
handler$<TIn, TOut>(fn: HandlerFn<TIn, TOut>): HandlerRef<TIn, TOut>
tool$<TIn, TOut>(config: ToolConfig<TIn, TOut>): ToolDefinition<TIn, TOut>
agent$(config: AgentConfig): AgentDefinition
skill$(config: SkillConfig): SkillDefinition
instructions$(text: string): InstructionsRef
projection$<TState>(config: ProjectionConfig<TState>): ProjectionDefinition<TState>
memory$(config: MemoryConfig): MemoryDefinition
policy$(config: PolicyConfig): PolicyDefinition
loadInstructions(spec: InstructionsSpec): Promise<string>   // resolve inline or lazy-chunked text
#+end_src

** Shared runtime types

These flow through the whole system.

** ~defineConfig~ (@loom/app)

The composition root: turns one static config into the same runtime + transport you would otherwise hand-assemble.

#+begin_src typescript
function defineConfig(config: LoomConfig): LoomApp

type StorageConfig =
  | { kind: "memory" }                                            // ephemeral (tests / browser)
  | { kind: "sqlite"; dir?: string; branching?: boolean }         // embedded, lazily loaded (Node)
  | { kind: "custom";                                             // BRING YOUR OWN backend
      eventStore: EventStore; snapshotStore: SnapshotStore; branchRegistry?: BranchRegistry };

interface LoomConfig {
  storage: StorageConfig;                       // required
  projectionRuntime?: ProjectionRuntime;        // default in-memory
  surfaces?: string[];                          // A2UI surfaces to register
  flows?: RegisteredFlow[];
  flowModules?: FlowModule[];                    // every RegisteredFlow-shaped export is registered
  manifest?: ManifestView;                       // cross-check vs compiler manifest
  onWarn?: (message: string) => void;            // default console.warn
  validate?: boolean | "warn" | "error";         // boot-time flow-graph validation
  catalog?: CatalogLike;                         // capability catalog
  agents?: AgentCard[];                          // advertised on the A2A bus
  capabilityAgents?: Record<string, string>;     // capabilityId → agentId
  effectMiddleware?: EffectMiddleware[];
  telemetry?: TelemetryAdapter[];
  dispatcher?: ExecutionDispatcher;              // placement (default: in-process)
  onEvent?: (event: EventEnvelope) => void;      // fired after projection + telemetry
}

interface LoomApp {
  runtime: WorkflowRuntime;
  effectRuntime: EffectRuntime;
  projectionRuntime: ProjectionRuntime;
  bus: InProcessA2ABus;
  stores: { eventStore: EventStore; snapshotStore: SnapshotStore; branchRegistry?: BranchRegistry };
  close(): Promise<void>;
}
#+end_src

*Bring your own storage:* ~kind: "custom"~ uses any async-first ~EventStore~/~SnapshotStore~ (+ optional ~BranchRegistry~) verbatim — Postgres/Redis/DynamoDB (see [[file:examples/postgres-backend/README.md][the Postgres reference]]). The SQLite stores are lazily loaded, so ~kind: "memory"~ never pulls ~better-sqlite3~/~node:fs~ into a browser bundle.

* WorkflowRuntime
:PROPERTIES:
:CUSTOM_ID: workflow-runtime

The durable execution engine (~@loom/workflow-runtime~). ~defineConfig~ returns one as ~app.runtime~; you can also construct it directly.

interface WorkflowRuntimeDeps {

class WorkflowRuntime {

** ~WorkflowContext~ — the flow API

The ~ctx~ handed to every runner. Every call is durable, ordered, and replayable.

#+begin_src typescript
interface WorkflowContext {
  readonly executionId: string;
  readonly workflowId: string;
  run<TIn, TOut>(step: StepDefinition<TIn, TOut>, input: TIn): Promise<TOut>;         // memoized on replay
  parallel<T extends unknown[]>(
    pairs: { [K in keyof T]: [StepDefinition<unknown, T[K]>, unknown] },
    options?: { limit?: number }
  ): Promise<T>;                                                                       // results ALWAYS in input order
  suspend(config: { on: string; timeout?: number; correlationKey?: string }): Promise<never>;
  emit(eventType: string, payload: unknown): void;                                     // durable domain event
  stream(eventType: string, delta: string, done?: boolean): void;                      // token streaming
  readonly ui: A2UIEmitter;                                                            // ctx.ui.set/merge/append …
}
#+end_src

* Effects — ~@loom/effect-runtime~
:PROPERTIES:
:CUSTOM_ID: effects
:END:

All side effects (tool / LLM / human / A2A) run through the ~EffectRuntime~, keyed by ~toolId~. On replay a completed effect is served from the log, never re-executed.

#+begin_src typescript
