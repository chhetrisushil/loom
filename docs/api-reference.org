* Builders
:PROPERTIES:
:CUSTOM_ID: builders
:END:

Builders are factory functions (suffixed with ~$~) that produce typed definition objects. Definitions are plain data — they carry no runtime state and can be serialized, stored, or sent over the wire.

** ~flow$~

Defines a workflow. A flow has an id, version, I/O schemas, and the steps it may execute.

#+begin_src typescript
import { flow$ } from "@loom/sdk";
import { z } from "zod";

const MyFlow = flow$({
  id: "my-flow",          // unique identifier — used for registration and resume
  name: "My Flow",        // human-readable label
  version: "1.0.0",       // semver — included in every EventEnvelope
  description: "...",     // optional
  inputSchema: z.object({ userId: z.string() }),
  outputSchema: z.object({ done: z.boolean() }),
  steps: [FetchStep, ProcessStep],  // StepDefinition[]
  policies: [RateLimitPolicy],      // optional PolicyDefinition[]
});
#+end_src

| Field          | Type                     | Required | Description                                     |
|----------------+--------------------------+----------+-------------------------------------------------|
| ~id~           | ~string~                 | yes      | Stable identifier; must be unique in the registry |
| ~name~         | ~string~                 | yes      | Display name                                    |
| ~version~      | ~string~                 | yes      | Stamped on every event emitted by this flow     |
| ~description~  | ~string~                 | no       | Optional documentation string                   |
| ~inputSchema~  | ~ZodSchema<TIn>~         | yes      | Validates ~start()~ input                       |
| ~outputSchema~ | ~ZodSchema<TOut>~        | yes      | Declares the shape of the runner's return value |
| ~steps~        | ~StepDefinition[]~       | yes      | All steps the runner may call                   |
| ~policies~     | ~PolicyDefinition[]~     | no       | Governance rules                                |

** ~step$~

Defines an individual unit of work within a flow. A step links to an effect via ~toolId~ (or co-locates the implementation with ~handler$~) and declares its own I/O schemas and retry policy.

#+begin_src typescript
import { step$, handler$ } from "@loom/sdk";
import { z } from "zod";

// Option A: co-located handler (recommended — no separate registration needed)
const FetchMetricsStep = step$({
  id: "fetch-metrics",
  toolId: "metrics-tool",
  inputSchema: z.object({ incidentId: z.string() }),
  outputSchema: z.object({
    cpu: z.object({ current: z.number(), threshold: z.number() }),
    memory: z.object({ usedMb: z.number(), totalMb: z.number() }),
  }),
  handler: handler$(async (input, ctx) => {
    const data = await fetchMetrics(input.incidentId);
    return data;
  }),
  retry: { maxAttempts: 3, backoffMs: 500, backoffMultiplier: 2 },
  timeoutMs: 10_000,
});

// Option B: toolId only (register effect separately via effectRuntime.register)
const ApplyStep = step$({
  id: "apply-fix",
  toolId: "fix-tool",
  inputSchema: z.object({ ticketId: z.string() }),
  outputSchema: z.object({ applied: z.boolean() }),
});
#+end_src

| Field          | Type              | Required | Description                                                      |
|----------------+-------------------+----------+------------------------------------------------------------------|
| ~id~           | ~string~          | yes      | Unique within the flow; used to key ~ExecutionFrame~             |
| ~name~         | ~string~          | no       | Display name; defaults to ~id~                                   |
| ~toolId~       | ~string~          | no       | Effect registry key; defaults to ~id~ if omitted                 |
| ~handler~      | ~HandlerSpec~     | no       | Co-located implementation via ~handler$()~ — auto-registered by ~registerFlow~ |
| ~inputSchema~  | ~ZodSchema~       | yes      | Input shape                                                      |
| ~outputSchema~ | ~ZodSchema~       | yes      | Output shape                                                     |
| ~retry~        | ~RetryPolicy~     | no       | ~{ maxAttempts, backoffMs?, backoffMultiplier? }~                |
| ~timeoutMs~    | ~number~          | no       | Per-attempt timeout in milliseconds                              |

** ~handler$~

Co-locates a step's handler implementation with its definition. At runtime, returns a ~HandlerRef~ (called directly by ~LazyEffect~). At build time, ~@loom/compiler~ rewrites it to a dynamic import thunk.

#+begin_src typescript
import { handler$ } from "@loom/sdk";

const myHandler = handler$(async (input: { id: string }, ctx) => {
  // ctx: { executionId, stepId, workflowId, attempt, emit }
  const result = await fetchData(input.id);
  ctx.emit("DATA_FETCHED", result);
  return result;
});

// Use inside step$:
const MyStep = step$({
  id: "my-step",
  handler: myHandler,
  inputSchema: ..., outputSchema: ...,
});
#+end_src

| Signature | ~handler$<TIn, TOut>(fn: HandlerFn<TIn, TOut>): HandlerRef<TIn, TOut>~ |
|-----------+------------------------------------------------------------------------|
| Runtime   | Returns ~{ _loomHandlerRef: true, fn }~ — zero overhead               |
| Build     | Compiler replaces with ~() => import("\0loom:chunk:<id>_<hash>")~     |

~HandlerFn~ signature:

#+begin_src typescript
type HandlerFn<TIn, TOut> = (input: TIn, ctx: StepHandlerContext) => Promise<TOut>;

interface StepHandlerContext {
  executionId: string;
  stepId: string;
  workflowId: string;
  attempt: number;           // 1-based retry count
  emit(eventType: string, payload: unknown): void;
}
#+end_src

** ~tool$~

Defines tool metadata. Use this when you want to describe a tool as a first-class definition separate from its implementation.

#+begin_src typescript
import { tool$ } from "@loom/sdk";

const MetricsTool = tool$({
  id: "metrics-tool",
  name: "Metrics Tool",
  description: "Fetches database performance metrics",
  kind: "tool",   // "tool" | "llm" | "human" | "a2a" — defaults to "tool"
  inputSchema: z.object({ incidentId: z.string() }),
  outputSchema: z.object({ cpu: z.number() }),
});
#+end_src

| Field         | Type         | Required | Description                               |
|---------------+--------------+----------+-------------------------------------------|
| ~id~          | ~string~     | yes      | Matches ~toolId~ on ~StepDefinition~      |
| ~name~        | ~string~     | yes      | Display name                              |
| ~description~ | ~string~     | yes      | Used by LLM tool-selection prompts        |
| ~kind~        | ~EffectKind~ | no       | ~"tool" \vert "llm" \vert "human" \vert "a2a"~; defaults to ~"tool"~ |
| ~inputSchema~ | ~ZodSchema~  | yes      | Input shape                               |
| ~outputSchema~| ~ZodSchema~  | yes      | Output shape                              |

** ~projection$~

Defines a read model that is derived by folding workflow events. Each handler is a pure reducer ~(state, event) => state~.

#+begin_src typescript
import { projection$ } from "@loom/sdk";
import type { EventEnvelope } from "@loom/sdk";

const MetricsProjection = projection$({
  id: "metrics",
  name: "Metrics Projection",
  sourceFlowId: "investigate-incident",  // optional — documentation only
  initialState: { cpu: null as number | null, memory: null as number | null },
  handlers: {
    INCIDENT_ANALYSIS_COMPLETE: (state, event: EventEnvelope) => {
      const payload = event.payload as { metrics: { cpu: number; memory: number } };
      return { cpu: payload.metrics.cpu, memory: payload.metrics.memory };
    },
  },
});
#+end_src

| Field          | Type                                          | Required | Description                                   |
|----------------+-----------------------------------------------+----------+-----------------------------------------------|
| ~id~           | ~string~                                      | yes      | Referenced in Blueprint ~DataBinding~ and ~BlueprintRenderer~ |
| ~name~         | ~string~                                      | yes      | Display name                                  |
| ~sourceFlowId~ | ~string~                                      | no       | Documentation — which flow produces this projection's events |
| ~initialState~ | ~TState~                                      | yes      | Starting value before any events are applied  |
| ~handlers~     | ~Record<string, (state, event) => state>~     | yes      | One entry per event type this projection handles |

** ~agent$~

Groups tools and policies into an agent definition. Agents are composable units for multi-agent architectures.

#+begin_src typescript
import { agent$ } from "@loom/sdk";

const InvestigatorAgent = agent$({
  id: "investigator",
  name: "Investigator Agent",
  description: "Gathers incident evidence",
  tools: [MetricsTool, LogsTool],
  policies: [RateLimitPolicy],
  memoryId: "incident-memory",   // optional — links to a MemoryDefinition
  // optional A2A AgentCard metadata — read by toAgentCard() (see @loom/a2a)
  version: "1.0.0",
  capabilities: { streaming: true },
  skills: [{ id: "investigate", name: "Investigate incident" }],
});
#+end_src

The optional ~version~, ~capabilities~, and ~skills~ fields describe how the agent is advertised over A2A. Co-locating them on the definition lets ~toAgentCard(agent)~ derive the agent's ~AgentCard~ instead of hand-authoring a parallel object (~skills~ is a ~AgentSkillDef[]~).

** ~skill$~ / ~instructions$~

Declares a *Skill*: a progressively-disclosed bundle of authored instructions (and an optional tool subset) an agent loads on demand. The ~description~ is cheap metadata always available for selection; the ~instructions$~ body is lazy — the compiler extracts it into its own chunk exactly as it does for ~handler$~, so only *selected* skills are ever pulled into context. This is the instruction/know-how axis, distinct from ~tool$~ (a function) and ~capability$~ (a runnable flow).

#+begin_src typescript
import { skill$, instructions$ } from "@loom/sdk";

const CpuRunbook = skill$({
  id: "diagnose-cpu",
  name: "Diagnose CPU saturation",
  description: "Root-cause CPU saturation and connection-pool exhaustion",
  tags: ["cpu", "pool"],
  instructions: instructions$(`
    1. Confirm CPU% and pool utilisation via the metrics tool before acting.
    2. If the pool is exhausted, recycle it and raise the ceiling — graceful and reversible.
    3. Only scale replicas if CPU stays high after the pool recovers.
  `),
  tools: [RestartPoolTool],   // optional — surfaced to the model when this skill is selected
});
#+end_src

| Builder | Purpose |
|---------+---------|
| ~skill$(config)~ | Produces a ~SkillDefinition~ (~{ id, name, description, tags?, instructions, tools? }~) |
| ~instructions$(text)~ | Marks the instruction body. Runtime: ~{ _loomInstructionsRef: true, text }~. Build: compiler rewrites to ~() => import("\0loom:chunk:<id>_<hash>")~ |
| ~loadInstructions(spec)~ | Resolves either form to its text (inline ref or compiler loader) |

Skills are not hung on ~agent$~; they are grouped in a ~SkillRegistry~ and passed to ~AgentRunner~ (see [[#agent][~@loom/agent~]]). Note: distinct from the A2A ~AgentSkillDef~ metadata on an agent card — that advertises a capability; a ~SkillDefinition~ injects runtime instruction context.

** ~memory$~

Declares a scoped memory store for an agent. The framework registers the definition; you supply the runtime implementation.

#+begin_src typescript
import { memory$ } from "@loom/sdk";

const IncidentMemory = memory$({
  id: "incident-memory",
  name: "Incident Memory",
  ttlMs: 60 * 60 * 1000,   // 1 hour
  maxEntries: 500,
});
#+end_src

** ~policy$~

Declares a governance policy with arbitrary rules. Policies are attached to flows or agents; enforcement is application-level.

import { policy$ } from "@loom/sdk";

const RateLimitPolicy = policy$({
  id: "rate-limit",
  name: "Rate Limit",

});
#+end_src

* ~defineConfig~ (@loom/app)
:PROPERTIES:
:CUSTOM_ID: app
:END:

The composition root. ~defineConfig~ assembles the runtime, stores, effect middleware, projection runtime, telemetry, and the in-process A2A bus from one static config, and returns the same primitives you would otherwise hand-wire — so nothing is hidden and you can always drop a level.

#+begin_src typescript
import { defineConfig } from "@loom/app";

const app = defineConfig({
  storage: { kind: "sqlite", dir: ".loom", branching: true },
  surfaces: ["mission"],
  flows: [myFlow],                 // or flowModules from `loom gen`
  effectMiddleware: [retryMiddleware({ maxRetries: 3 })],
  agents, capabilityAgents,        // A2A routing
  validate: "warn",               // static flow-graph checks at boot
});
// → { runtime, effectRuntime, projectionRuntime, bus, stores, close }
const handle = await app.runtime.start(myFlow, input);
#+end_src

** ~LoomConfig~

| Field                | Type                                                   | Notes |
|----------------------+--------------------------------------------------------+-------|
| ~storage~            | ~StorageConfig~ (see below)                            | required |
| ~surfaces~           | ~string[]~                                             | A2UI surfaces to register |
| ~flows~              | ~RegisteredFlow[]~                                     | flows to register |
| ~flowModules~        | ~FlowModule[]~                                         | static modules from ~loom gen~ (every ~RegisteredFlow~-shaped export is registered) |
| ~effectMiddleware~   | ~EffectMiddleware[]~                                   | ~(ctx, input, next)~ chain (retries, logging, …) |
| ~validate~           | ~boolean \vert "warn" \vert "error"~                   | boot-time flow-graph validation |
| ~projectionRuntime~  | ~ProjectionRuntime~                                    | bring a custom one (coalescing / broadcasting) |
| ~catalog~            | ~CatalogLike~                                          | capability catalog registered into the runtime |
| ~agents~             | ~AgentCard[]~                                          | advertised on the A2A bus |
| ~capabilityAgents~   | ~Record<string,string>~                                | capabilityId → agentId routing |
| ~telemetry~          | ~TelemetryAdapter[]~                                   | composed + wired to the event stream |
| ~dispatcher~         | ~ExecutionDispatcher~                                  | placement (in-process / remote / Cloud Run) |
| ~onEvent~            | ~(e: EventEnvelope) => void~                           | extra observer, after projection + telemetry |
| ~onWarn~             | ~(message: string) => void~                            | sink for boot warnings |

** ~StorageConfig~ — including Bring-Your-Own backend

#+begin_src typescript
type StorageConfig =
  | { kind: "memory" }                                           // ephemeral (tests / browser)
  | { kind: "sqlite"; dir?: string; branching?: boolean }        // embedded, lazily loaded (Node)
  | { kind: "custom";                                            // bring your own backend
      eventStore: EventStore; snapshotStore: SnapshotStore; branchRegistry?: BranchRegistry };
#+end_src

~kind: "custom"~ takes any async-first ~EventStore~/~SnapshotStore~ (+ optional ~BranchRegistry~) — Postgres, Redis, DynamoDB — used verbatim, so a network-backed app gets the same composition root as everyone else (see [[file:examples/postgres-backend/README.md][the Postgres reference]]). The SQLite stores are lazily loaded, so ~kind: "memory"~ never pulls ~better-sqlite3~/~node:fs~ into a browser bundle.

** DX & operations (built on the durable log)

Each of these is a separate package; all are lenses on the same event log.

- *~@loom/testing~* — ~createTestApp(config?)~ (in-memory ~LoomApp~), ~waitFor~/~waitForPhase~, ~getSurfaceState~, ~driveToSuspend~/~resumeWith~, ~captureGolden~, and a VCR LLM provider (~recordingProvider~/~replayingProvider~).
- *~@loom/eval~* — replay a recorded log as a fixture; ~diffRuns~/~scoreRun~. Driven by ~loom eval --dir evals/~.
- *~@loom/deploy-sim~* — ~simulateDeploy(logs, resolver)~ replays history against new flow definitions to catch resume-breaking changes. Driven by ~loom deploy check~.
- *The ~loom~ CLI* (~@loom/cli~) — ~logs~ / ~debug --at N~ (time-travel) / ~inspect~ (web timeline + slider) / ~eval~ / ~deploy check~ / ~check~ / ~gen~ / ~new~.
- *~@loom/middleware~* — ~retryMiddleware(options)~: exponential backoff with *deterministic* jitter; never retries a suspension.
- *Compute* — ~@loom/dispatcher~ (~ExecutionDispatcher~ / ~LocalDispatcher~), ~@loom/worker-runtime~ (SPI + ~ExecutionPackage~), ~-local~/~-remote~, ~@loom/worker-server~ (~POST /execute~), ~@loom/platform-cloudrun~ (~CloudRunWorkerRuntime~), ~@loom/graph-executor~ (~executeGraph~).
- *~@loom/orchestrator~* — ~decideApproval(policy, handlers)~ (risk gate) + ~dispatchPlan~.

* WorkflowRuntime
:PROPERTIES:
:CUSTOM_ID: workflow-runtime
:END:

~WorkflowRuntime~ orchestrates flow execution. Construct one instance per application; it is safe to share across concurrent flow executions.

#+begin_src typescript
import { WorkflowRuntime } from "@loom/sdk";
import { SqliteEventStore } from "@loom/event-runtime";
import { SqliteSnapshotStore } from "@loom/snapshot-runtime";
import { EffectRuntime, ToolEffect } from "@loom/effect-runtime";

const effectRuntime = new EffectRuntime();
const eventStore = new SqliteEventStore("./data/events.db");
const snapshotStore = new SqliteSnapshotStore("./data/snapshots.db");

const runtime = new WorkflowRuntime({
  eventStore,
  snapshotStore,
  effectRuntime,
  onEvent: (event) => projectionRuntime.handleEvent(event),  // optional
});
#+end_src

** Constructor options

| Option          | Type                                  | Required | Description                                               |
|-----------------+---------------------------------------+----------+-----------------------------------------------------------|
| ~eventStore~    | ~EventStore~                          | yes      | Where events are persisted                                |
| ~snapshotStore~ | ~SnapshotStore~                       | yes      | Where suspend-point snapshots are stored                  |
| ~effectRuntime~ | ~EffectRuntime~                       | yes      | Registry of effect handlers                               |
| ~onEvent~       | ~(event: EventEnvelope) => void~      | no       | Called synchronously after every event is folded — wire to ProjectionRuntime |
| ~branchRegistry~ | ~BranchRegistry~                     | no       | Enables ~fork()~ to record lineage + refs (see [[#branch-registry][BranchRegistry]]) |
| ~onStorageError~ | ~(executionId, err) => void~         | no       | Observability hook for a durable-write rejection (the async storage failure mode). The run aborts and ~waitForCompletion~/~waitForSuspend~ reject with a ~StorageWriteError~ regardless. |

** ~registerFlow(definition, runner)~

Registers a flow so it can be found during ~resume()~. Call before any ~start()~ or ~resume()~ for that flow.

#+begin_src typescript
runtime.registerFlow(
  InvestigateIncidentFlow.definition,
  InvestigateIncidentFlow.runner
);
#+end_src

Both ~definition~ (~FlowDefinition~) and ~runner~ (~FlowRunner~) must be provided. The runtime looks up registered flows by ~definition.id~ when resuming a suspended execution.

** ~start(flow, input, options?)~

Starts a new execution. Returns an ~ExecutionHandle~ immediately (the flow runs asynchronously in the background).

#+begin_src typescript
const handle = await runtime.start(
  InvestigateIncidentFlow,        // RegisteredFlow
  { incidentId: "cpu-001" },      // TIn — must satisfy inputSchema
  { executionId: "exec-abc" }     // optional RunOptions
);
#+end_src

| Option        | Type     | Description                                                |
|---------------+----------+------------------------------------------------------------|
| ~executionId~ | ~string~ | Pin the execution to a specific id; auto-generated (ULID) if omitted |

** ~resume(executionId, resumeEvent)~

Resumes a suspended execution. Appends the resume event, loads the latest snapshot, and re-runs the flow runner from the beginning (with previously completed steps replayed from cache).

#+begin_src typescript
const handle = await runtime.resume("exec-abc", {
  eventType: "ApprovalGranted",
  payload: { approved: true, approvedBy: "operator@example.com" },
});
#+end_src

| Field       | Type      | Description                                              |
|-------------+-----------+----------------------------------------------------------|
| ~eventType~ | ~string~  | The event type the flow was waiting for in ~ctx.suspend()~ |
| ~payload~   | ~unknown~ | Data delivered to the flow after the suspend point       |

Throws ~WorkflowNotFoundError~ if ~executionId~ has no recorded events.

** ~restoreFromState(preloadedState, resumeEvent?)~

Client-side restoration path. Accepts a pre-deserialized ~ExecutionState~ (produced server-side by ~serializeExecution~) and reconstructs an execution without reading the EventStore. Optionally delivers a resume event atomically.

#+begin_src typescript
import { deserializeExecution } from "@loom/workflow-runtime";

// On client, after receiving serialized state from server
const preloadedState = deserializeExecution(serializedString);

const handle = await runtime.restoreFromState(preloadedState, {
  eventType: "ApprovalGranted",
  payload: { approved: true },
});

handle.waitForCompletion().then(() => console.log("Done"));
#+end_src

| Parameter       | Type             | Required | Description                                             |
|-----------------+------------------+----------+---------------------------------------------------------|
| ~preloadedState~| ~ExecutionState~ | yes      | Deserialized snapshot from ~deserializeExecution~       |
| ~resumeEvent~   | ~ResumeEvent~    | no       | Optional event to append before re-running the flow    |

The corresponding flow must already be registered via ~registerFlow()~ before calling ~restoreFromState~.

** ~fork(parentExecutionId, atSequence, opts?)~

Forks an execution at ~atSequence~ into an independent branch for speculative work. Copy-on-write over the event log: the parent's events ~[0..atSequence]~ are copied into a new child ~executionId~ and a seed snapshot is written at the fork point, so the child re-derives the identical pre-fork state (cached step outputs are *not* re-run) and the parent log is never touched. Returns a ~ForkResult~ — it does *not* start execution; drive the branch with ~resume()~ or ~restoreFromState()~. Branch-only: there is no merge — pick a winner with ~branchRegistry.promote()~.

#+begin_src typescript
// Fork a suspended task at its approval gate.
const branch = await runtime.fork("task-abc", 7, {
  branchName: "spec/scale-replicas",
});

// Drive the branch down an alternate path...
await runtime.resume(branch.executionId, {
  eventType: "ApprovalGranted",
  payload: { approved: true, approvedBy: "operator" },
});

// ...then keep the winner (a pointer move, not a merge):
branchRegistry.promote("spec/scale-replicas", "main");
#+end_src

| Parameter          | Type          | Required | Description                                                    |
|--------------------+---------------+----------+----------------------------------------------------------------|
| ~parentExecutionId~ | ~string~     | yes      | The execution to branch from                                   |
| ~atSequence~       | ~number~      | yes      | Fork point; must be in ~0..tip~ (throws otherwise)             |
| ~opts.branchName~  | ~string~      | no       | Registers a movable ref for the branch (needs ~branchRegistry~) |
| ~opts.executionId~ | ~string~      | no       | Pin the child id; auto-generated (ULID) if omitted             |

Returns ~ForkResult~: ~{ executionId, parentExecutionId, forkSequence, branchName, state }~, where ~state~ is the materialized ~ExecutionState~ at the fork point (already stamped with the child id). Forking records lineage/ref bookkeeping only when a ~branchRegistry~ was supplied to the runtime, and introduces *no new event type* — provenance lives in event ~metadata~.

** ~register(toolId, effect)~

Convenience proxy that forwards to the underlying ~EffectRuntime~. Equivalent to calling ~effectRuntime.register()~ directly.

#+begin_src typescript
runtime.register("metrics-tool", new ToolEffect(async (input) => ({
  cpu: { current: 87, threshold: 80 },
})));
#+end_src

* WorkflowContext — the flow API
:PROPERTIES:
:CUSTOM_ID: workflow-context
:END:

~WorkflowContext~ is the object injected as the first argument to every ~FlowRunner~ function. It is the complete API available inside a flow.

#+begin_src typescript
type FlowRunner<TIn, TOut> = (ctx: WorkflowContext, input: TIn) => Promise<TOut>;
#+end_src

** ~ctx.run(step, input)~

Executes a step. If the step already completed in a previous run (detected via ~ReplayVM~), returns the cached output without calling the effect again. This is the primary idempotency guarantee.

#+begin_src typescript
const metrics = await ctx.run(FetchMetricsStep, { incidentId: input.incidentId });
// metrics: { cpu: { current: 87, ... }, memory: { ... } }
#+end_src

- Emits ~STEP_STARTED~ before execution and ~STEP_COMPLETED~ (or ~STEP_FAILED~) after.
- On failure, re-throws the error after emitting ~STEP_FAILED~.
- The ~toolId~ on the ~StepDefinition~ determines which registered effect is called; falls back to ~step.id~ if ~toolId~ is not set.

** ~ctx.parallel(pairs)~

Runs multiple steps concurrently with ~Promise.all~. Each pair is ~[StepDefinition, input]~. Returns a tuple of outputs in the same order.

#+begin_src typescript
const [metrics, logs] = await ctx.parallel([
  [FetchMetricsStep, { incidentId: input.incidentId }],
  [FetchLogsStep,    { incidentId: input.incidentId }],
]);
#+end_src>

Idempotency works the same as ~ctx.run~ — completed steps return cached results immediately.

Pass an optional second argument for *bounded* concurrency — useful for large fan-outs that would otherwise open too many effects at once:

#+begin_src typescript
const results = await ctx.parallel(
  incidentIds.map((id) => [FetchMetricsStep, { incidentId: id }] as const),
  { limit: 4 },   // at most 4 steps run concurrently
);
#+end_src

| Option   | Type     | Default            | Description                                       |
|----------+----------+--------------------+---------------------------------------------------|
| ~limit~  | ~number~ | unbounded          | Max steps running at once; ~≤ 0~ means unbounded  |

~limit~ is powered by ~parallelLimit~ from [[#scheduler][~@loom/scheduler~]]. Results are *always* returned in input order regardless of completion order, so replay stays deterministic; the default (no ~options~) is unchanged ~Promise.all~ behaviour. When the execution is cancelled, ~ctx.signal~ is forwarded so queued tasks abort promptly (see [[#execution-handle][cancellation]]).

** ~ctx.emit(eventType, payload)~

Appends a custom domain event to the event log. Triggers ~onEvent~ on the runtime (which routes to ~ProjectionRuntime~), so UI projections update immediately.

#+begin_src typescript
ctx.emit("INCIDENT_ANALYSIS_COMPLETE", { metrics, logs, timestamp: Date.now() });
#+end_src

Use ~ctx.emit~ to push domain-meaningful events that projections can react to. Structural events (~STEP_STARTED~, ~EXECUTION_SUSPENDED~, etc.) are emitted automatically.

** ~ctx.ui~ — the A2UI emitter

Every ~WorkflowContext~ carries a pre-wired ~ui: A2UIEmitter~ (from ~@loom/a2ui~) bound to the default ~"ui"~ surface. Each call emits one ~A2UI_PATCH~ event through the normal ~ctx.emit~ pipeline, so UI updates are durable and replay deterministically — the surface rebuilds itself by folding the same patch events on resume.

#+begin_src typescript
// Address surface state by dot-notation path ("" is the root)
ctx.ui.set("phase", "analyzing");
ctx.ui.merge("metrics", { cpu: 87 });
ctx.ui.append("log", "fetched metrics");     // push onto an array
ctx.ui.increment("progress", 10);            // numeric bump (default +1)
ctx.ui.set("done", true);
#+end_src

See [[#a2ui][~@loom/a2ui~]] for the full emitter, patch, and consumer API. ~ctx.stream(eventType, delta, done?)~ remains as low-level sugar over ~ctx.emit~ for pushing ~{ delta, done }~ payloads.

** ~ctx.suspend(config)~

Suspends the workflow. On a fresh run, throws ~SuspendError~ (caught by ~WorkflowRuntime~, which saves a snapshot and resolves ~waitForSuspend()~). On resume replay, passes through transparently so the runner continues past the suspend point.

#+begin_src typescript
await ctx.suspend({
  on: "ApprovalGranted",              // event type that resumes this execution
  correlationKey: input.incidentId,   // optional — for routing in multi-instance setups
  timeout: 24 * 60 * 60 * 1000,      // optional — milliseconds
});
// Code here runs only after resume
#+end_src

| Field            | Type     | Required | Description                                               |
|------------------+----------+----------+-----------------------------------------------------------|
| ~on~             | ~string~ | yes      | The ~eventType~ expected in ~runtime.resume()~           |
| ~correlationKey~ | ~string~ | no       | Scopes the resume to a specific entity                    |
| ~timeout~        | ~number~ | no       | How long to wait before failing (enforcement is app-level)|

** ~ctx.executionId~ / ~ctx.workflowId~

Read-only strings identifying the current execution and its parent workflow.

* ExecutionHandle
:PROPERTIES:
:CUSTOM_ID: execution-handle
:END:

Both ~start()~ and ~resume()~ return an ~ExecutionHandle~ synchronously. Set up listeners before the async runner fires.

#+begin_src typescript
interface ExecutionHandle {
  executionId: string;
  waitForSuspend(): Promise<ExecutionState>;
  waitForCompletion(): Promise<ExecutionState>;
  getState(): ExecutionState;
  cancel(reason?: unknown): void;
}
#+end_src

| Member               | Description                                                              |
|----------------------+--------------------------------------------------------------------------|
| ~executionId~        | The unique id for this execution                                         |
| ~waitForSuspend()~   | Resolves with ~ExecutionState~ when the flow hits ~ctx.suspend()~        |
| ~waitForCompletion()~| Resolves with ~ExecutionState~ when the flow returns (or rejects on ~EXECUTION_FAILED~) |
| ~getState()~         | Synchronous snapshot of the current ~ExecutionState~                     |
| ~cancel(reason?)~    | Aborts in-flight effects, records a durable ~EXECUTION_CANCELLED~ event, and rejects ~waitForCompletion()~ |

** ~cancel(reason?)~ — cooperative cancellation

Aborts the execution's *live* work. It aborts the ~AbortSignal~ threaded into every in-flight effect (which cooperative effects forward to ~fetch~/providers), appends a durable ~EXECUTION_CANCELLED~ event, and rejects ~waitForCompletion()~ with ~reason~. It is *idempotent* — repeated calls record the event only once.

#+begin_src typescript
const handle = await runtime.start(InvestigateIncidentFlow, { incidentId: "cpu-001" });

// Later — user navigates away or a newer request supersedes this one:
handle.cancel(new Error("superseded by newer request"));

await handle.waitForCompletion().catch((err) => {
  // err === the reason passed to cancel()
  console.log("cancelled:", err.message);
});
handle.getState().status;   // → "cancelled"
#+end_src

Cancellation touches only *live* work: it does not delete persisted events or snapshots, so a cancelled execution can still be inspected and its resume semantics are unchanged. The runtime emits two new event types:

- ~EXECUTION_CANCELLED~ — sets the execution ~status~ to ~"cancelled"~.
- ~STEP_CANCELLED~ — set on a frame whose effect was aborted; marks that frame's ~status~ ~"cancelled"~ but leaves the execution status alone. ~ctx.run~ emits this (instead of ~STEP_FAILED~) when the effect rejects because ~ctx.signal~ was aborted.

Both ~ExecutionStatus~ and ~FrameStatus~ gain the ~"cancelled"~ value.

~waitForSuspend()~ and ~waitForCompletion()~ are independent — await whichever is relevant:

#+begin_src typescript
const handle = await runtime.start(MyFlow, input);

// Wait for first suspend
handle.waitForSuspend().then((state) => {
  console.log("Suspended at sequence", state.sequence);
  showApprovalUI();
});

// Always log completion
handle.waitForCompletion()
  .then(() => console.log("Done"))
  .catch((err) => console.error("Failed", err));
#+end_src

~EffectRuntime~ is a registry that maps ~toolId~ strings to ~Effect~ implementations. Every side effect a flow executes must be registered here.

** ~EffectRuntime~

|-----------------------------------+-----------------------------------------------------------|

** ~ToolEffect~

Wraps a plain async function. Use for HTTP calls, database queries, file I/O, or any deterministic external call.

#+begin_src typescript
import { ToolEffect } from "@loom/effect-runtime";

effectRuntime.register(
  "metrics-tool",
  new ToolEffect(async (input: { incidentId: string }, ctx) => {
    const data = await fetchMetrics(input.incidentId);

    return data;
  })

#+end_src

The function receives ~(input: TIn, ctx: EffectContext)~.

** ~LlmEffect~

Same shape as ~ToolEffect~, semantically tagged as an LLM call. Use for prompting a language model.

#+begin_src typescript
import { LlmEffect } from "@loom/effect-runtime";

effectRuntime.register(
  "summarize-logs",

  })
);
#+end_src

** ~HumanEffect~

Immediately suspends the workflow to wait for human input. No async work is performed — the suspension itself is the effect. The workflow resumes when the application calls ~runtime.resume()~ with the matching ~eventType~.

effectRuntime.register(
  "approval-gate",

const ApprovalStep = step$({

** ~A2AEffect~

Agent-to-agent delegation. Structurally identical to ~ToolEffect~ — use it to call another Loom workflow or an external agent.

** ~LazyEffect~

The bridge between ~handler$()~ and the effect runtime. Accepts a ~HandlerSpec~ (either a ~HandlerRef~ or a ~HandlerLoader~), resolves the underlying function on the first ~execute()~ call, and caches it for subsequent calls.

You do not normally instantiate ~LazyEffect~ directly — ~WorkflowRuntime.registerFlow()~ creates one automatically for every step with a ~handler~ field.

#+begin_src typescript
import { LazyEffect } from "@loom/effect-runtime";

// HandlerRef path (runtime — handler$ without compiler)

effectRuntime.register("my-step", new LazyEffect(ref));

// HandlerLoader path (build time — compiler output)
const loader = () => import("./chunks/my-step_abc123");
effectRuntime.register("my-step", new LazyEffect(loader));
#+end_src

| Path          | When used                          | Resolution                                    |
|---------------+------------------------------------+-----------------------------------------------|
| ~HandlerRef~  | Runtime / tests / ts-node          | Calls ~ref.fn~ directly (zero overhead)       |
| ~HandlerLoader~ | After compiler transform         | ~await loader()~ on first call, caches result |

** ~EffectContext~

Passed as the second argument to every effect function.

#+begin_src typescript
interface EffectContext {
  executionId: string;
  stepId: string;
  workflowId: string;
  attempt: number;                                    // 1-based retry count
  emit(eventType: string, payload: unknown): void;   // emit events from within an effect
  readonly signal?: AbortSignal;                     // cooperative cancellation (see below)
}
#+end_src>

~signal~ is an optional ~AbortSignal~ that aborts when the owning execution is cancelled via ~ExecutionHandle.cancel()~. It is *undefined by default*, so non-cancellable effects pay nothing. Long-running / I/O effects (LLM, tool, A2A) should forward it to ~fetch~ (and to ~LlmRequest.signal~ / provider calls) and check it at await points so a cancel takes effect promptly:

#+begin_src typescript
new ToolEffect(async (input: { url: string }, ctx) => {
  const res = await fetch(input.url, { signal: ctx.signal });   // aborts on cancel
  return res.json();
});
#+end_src>

* EventStore
:PROPERTIES:
:CUSTOM_ID: event-store
:END:

~EventStore~ is the append-only log of all workflow events. It is *async-first* — every method returns a ~Promise~, so any backend plugs in (sync stores just mark methods ~async~; async/network stores return real Promises). The runtime ~await~s the store.

** Interface

#+begin_src typescript
interface EventStore {
  append(envelope: EventEnvelope): Promise<void>;
  read(executionId: string): Promise<EventEnvelope[]>;
  readFrom(executionId: string, fromSequence: number): Promise<EventEnvelope[]>;
  subscribe(executionId: string, handler: (event: EventEnvelope) => void): Promise<() => void>;
  close(): Promise<void>;
}
#+end_src

| Method              | Description                                                                |
|---------------------+----------------------------------------------------------------------------|
| ~append~            | Appends one event; rejects on duplicate ~(executionId, sequence)~          |
| ~read~              | Returns all events for an execution, ordered by sequence ascending         |
| ~readFrom~          | Returns events from ~fromSequence~ inclusive                               |
| ~subscribe~         | Calls ~handler~ after each ~append~; resolves to an unsubscribe fn (async so network stores can set up ~LISTEN~) |
| ~close~             | Releases the underlying resource (SQLite connection, etc.)                 |

There is no ~nextSequence~: sequence allocation is owned by the runtime's per-execution ~ExecutionJournal~, so a backend never does a read-then-write round-trip. ~SqliteEventStore~ and ~SqliteSnapshotStore~ are exported from ~@loom/sdk~. ~InMemoryAsyncEventStore~ / ~InMemoryAsyncSnapshotStore~ are reference async backends (with latency/failure injection) — a starting point for a real network store and used in the async test suite. See [[file:examples/postgres-backend/README.md][the Postgres reference]].

** ~SqliteEventStore~

Durable, WAL-mode SQLite store for server/production use.

#+begin_src typescript
import { SqliteEventStore } from "@loom/event-runtime";

const eventStore = new SqliteEventStore("./data/events.db");
// ...
eventStore.close();
#+end_src

** ~InMemoryEventStore~ (browser/testing)

Exists in the browser bundles and test setups. Not exported from ~@loom/event-runtime~ — instantiate via the example's ~browserStores~ or write your own:

#+begin_src typescript
// Minimal in-memory implementation for tests
class InMemoryEventStore implements EventStore {
  private log: EventEnvelope[] = [];
  append(e: EventEnvelope) { this.log.push(e); }
  read(id: string) { return this.log.filter(e => e.executionId === id); }
  // ...
}
#+end_src

** ~EventEnvelope~ shape

#+begin_src typescript
interface EventEnvelope {
  id: string;           // globally unique (executionId + sequence)
  workflowId: string;
  executionId: string;
  eventType: string;    // e.g. "STEP_COMPLETED", "APPROVAL_REQUESTED"
  sequence: number;     // monotonically increasing per execution
  timestamp: number;    // Date.now() at append time
  payload: unknown;     // event-specific data
  metadata?: Record<string, unknown>;
}
#+end_src

* BranchRegistry
:PROPERTIES:
:CUSTOM_ID: branch-registry
:END:

~BranchRegistry~ (in ~@loom/event-runtime~) holds git-style *movable refs* + immutable *fork lineage* for speculative branching. Pass one to ~WorkflowRuntime~ to enable [[#workflow-runtime][~fork()~]]; ~promote()~ picks a winner. Branch-only — there is no merge (two divergent ~ExecutionState~s have no principled join).

** Interface

#+begin_src typescript
// Async-first, like the other stores — every method returns a Promise.
interface BranchRegistry {
  putRef(ref: BranchRef): Promise<void>;          // create OR move (upsert by name)
  getRef(name: string): Promise<BranchRef | null>;
  listRefs(): Promise<BranchRef[]>;
  moveTip(name: string, tip: number): Promise<void>;      // advance a head as it grows
  promote(fromName: string, toName: string): Promise<void>; // pick-a-winner (pointer move)
  deleteRef(name: string): Promise<void>;

  recordLineage(rec: Omit<LineageRecord, "createdAt">): Promise<void>;
  getLineage(executionId: string): Promise<LineageRecord | null>;
  children(executionId: string): Promise<LineageRecord[]>;  // direct forks of an execution
  close(): Promise<void>;
}

interface BranchRef {
  name: string;                 // "main", "spec/scale-replicas"
  executionId: string;          // the execution this ref points at
  tip: number;                  // latest known sequence on that head
  parentExecutionId?: string;   // if created by a fork
  forkSequence?: number;        // if created by a fork
  createdAt: number;
  updatedAt: number;
}

interface LineageRecord {
  executionId: string;          // the child (forked) execution
  parentExecutionId: string;
  forkSequence: number;
  createdAt: number;
}
#+end_src

~promote("spec/x", "main")~ copies ~spec/x~'s ~(executionId, tip)~ onto ~main~ — a pointer move, no history rewrite. The losing branch stays an immutable, independently resumable execution.

** ~SqliteBranchRegistry~

#+begin_src typescript
import { SqliteBranchRegistry } from "@loom/event-runtime";

// Its own DB file — the refs/lineage tables are independent of the event log,
// so its writes never contend with the busy event-store write lock.
const branchRegistry = new SqliteBranchRegistry("./data/branches.db");

const runtime = new WorkflowRuntime({ eventStore, snapshotStore, effectRuntime, branchRegistry });
// ...
branchRegistry.close();
#+end_src

* SnapshotStore
:PROPERTIES:
:CUSTOM_ID: snapshot-store
:END:

~SnapshotStore~ caches ~ExecutionState~ at suspension points to avoid replaying the full event log on every resume.

** Interface

#+begin_src typescript
// Async-first, like EventStore.
interface SnapshotStore {
  save(snapshot: Snapshot): Promise<void>;
  loadLatest(executionId: string): Promise<Snapshot | null>;

  // Greatest snapshot AT OR BELOW `sequence` — used by WorkflowRuntime.fork()
  // to materialize state at a fork point without folding the log from zero.

}

interface Snapshot {

  executionId: string;
  workflowId: string;
  sequence: number;     // the event sequence at the time of the snapshot
  state: ExecutionState;
  createdAt: number;
}
#+end_src

* ProjectionRuntime
:PROPERTIES:
:CUSTOM_ID: projection-runtime
:END:

~ProjectionRuntime~ maintains live read models derived from the event stream. Wire it to ~WorkflowRuntime.onEvent~ and it stays up to date automatically.

** ~InMemoryProjectionRuntime~

#+begin_src typescript
import { InMemoryProjectionRuntime } from "@loom/projection-runtime";

const projectionRuntime = new InMemoryProjectionRuntime();
projectionRuntime.register(MetricsProjection);
projectionRuntime.register(IncidentProjection);

const runtime = new WorkflowRuntime({
  // ...
  onEvent: (event) => projectionRuntime.handleEvent(event),
});
#+end_src

*** Notification coalescing

The constructor accepts an optional ~config~:

#+begin_src typescript
const projectionRuntime = new InMemoryProjectionRuntime({
  coalesceNotifications: true,   // default false
});
#+end_src

| Option                   | Type      | Default | Description                                                        |
|--------------------------+-----------+---------+--------------------------------------------------------------------|
| ~coalesceNotifications~  | ~boolean~ | ~false~ | Batch subscriber notifications and flush once per microtask        |

When ~true~, subscriber notifications produced during a synchronous ~handleEvent~ burst are collected and flushed once per microtask, each subscriber receiving its projection's *latest* state. This collapses O(events) subscriber calls into O(microtask) — valuable for high-frequency streams such as LLM token deltas. State is still updated synchronously (~getState~ is always current); only the *notification* is deferred. Off by default, preserving synchronous notification semantics. Pairs well with ~useDeferredProjection~ / ~useDeferredWidgetValue~ on the React side.

** Interface

#+begin_src typescript
interface ProjectionRuntime {
  register<TState>(projection: Projection<TState>): void;
  getState<TState>(projectionId: string, executionId: string): TState;
  subscribe<TState>(
    projectionId: string,
    executionId: string,
    handler: (state: TState) => void
  ): () => void;         // returns unsubscribe function
  handleEvent(event: EventEnvelope): void;
  seedState(projectionId: string, executionId: string, state: unknown): void;
}
#+end_src

| Method        | Description                                                                      |
|---------------+----------------------------------------------------------------------------------|
| ~register~    | Adds a projection; must be called before the first event that triggers a handler |
| ~getState~    | Synchronous read of current state; returns ~initialState~ if no events yet       |
| ~subscribe~   | Registers a live listener; called synchronously after every matching event       |
| ~handleEvent~ | Routes an event to all registered projections; call from ~onEvent~              |
| ~seedState~   | Populates state directly without processing events — used by ~LoomProvider~ for client-side restore |

** ~seedState(projectionId, executionId, state)~

Directly sets projection state for a given ~(projectionId, executionId)~ pair, bypassing event processing. Used by ~LoomProvider~ to restore server-serialized projection state synchronously before the first render.

#+begin_src typescript
// Manual usage (LoomProvider does this automatically from serializedProjectionState)
const snapshot = deserializeProjections(serializedString);
for (const [projId, state] of Object.entries(snapshot.states)) {
  projectionRuntime.seedState(projId, snapshot.executionId, state);
}
#+end_src

** ~Projection~ shape

#+begin_src typescript
interface Projection<TState> {
  id: string;
  initialState: TState;
  handlers: {
    [eventType: string]: (state: TState, event: EventEnvelope) => TState;
  };
}
#+end_src

State keys are scoped to ~projectionId::executionId~, so concurrent executions of the same flow maintain separate state.

** Using ~projection$~ builder

#+begin_src typescript
import { projection$ } from "@loom/sdk";

  name: "Incident Projection",
  initialState: {

    INCIDENT_INVESTIGATION_STARTED: (state, event) => ({
      ...state,
      timeline: [...state.timeline, { message: "Investigation started", timestamp: event.timestamp }],
    }),
    APPROVAL_REQUESTED: (state) => ({
      ...state,
      pendingApproval: true,
    }),
    INCIDENT_RESOLVED: (state, event) => ({
      ...state,
      pendingApproval: false,
      timeline: [...state.timeline, { message: (event.payload as any).summary, timestamp: event.timestamp }],
    }),
  },
});
#+end_src

** Widget builders

All widgets share a ~binding~ field that resolves a dot-path in a projection's state.

#+begin_src typescript
type DataBinding = {
  projectionId: string;  // matches a registered Projection id
  path: string;          // dot-separated path into the projection state, e.g. "cpu.current"
};
#+end_src

An *empty* ~path~ (~""~) binds the widget to the *whole* projection surface (the root state object), not a nested field — use it for a widget that renders across several keys of one surface at once (e.g. a control panel or a git-style branch graph reading ~phase~, ~branches~, and ~refs~ together). | Builder       | Key props                                                        | Bound value shape         |
|---------------+------------------------------------------------------------------+---------------------------|
| ~MetricCard~  | ~title, unit?, format?~                                          | ~number \vert string~     |

| ~AlertCard~   | ~title?, severity?: "info" \vert "warning" \vert "error" \vert "critical"~ | ~string~ (alert message) |

Widget ids are deterministically hashed from ~(kind, props)~, so blueprints are stable across re-renders without explicit keys.

** ~traverseBlueprint~ vs ~traverseBlueprintAsync~

The synchronous ~traverseBlueprint~ is a *pull* traversal: it assembles the whole node tree bottom-up and hands it back. It is the default for renderers that need the complete tree (React, string/SSR) and is *unchanged*.

~traverseBlueprintAsync~ is an interruptible, incremental-commit (*push*) counterpart for scheduler-less BYOR renderers that mutate a target as the tree resolves (direct DOM, canvas, native). It creates each node top-down, appends children as they resolve, cooperatively yields against a budget, and honours an ~AbortSignal~ at every node — so a stale render can be interrupted and a large tree stays responsive.

#+begin_src typescript
import { traverseBlueprintAsync } from "@loom/blueprint-runtime";
import type { IncrementalRenderer } from "@loom/blueprint-runtime";

async function traverseBlueprintAsync<TNode>(
  node: Layout | Widget,
  stateMap: Map<string, unknown>,
  options: {
    renderer: IncrementalRenderer<TNode>;
    onAction?: (action: WidgetAction) => void;
    signal?: AbortSignal;                        // checked at every node
    shouldYield?: (nodesSinceYield: number) => boolean;   // default: every 64 nodes
    yieldTo?: () => Promise<void>;               // default: @loom/scheduler yieldControl
  },
): Promise<TNode>;

interface IncrementalRenderer<TNode> {
  createContainer(layout: Layout): TNode;
  createWidget(ctx: WidgetRendererProps): TNode;
  appendChild(parent: TNode, child: TNode): void;
}
#+end_src

#+begin_src typescript
// A minimal DOM IncrementalRenderer (no React, no virtual tree)
const domRenderer: IncrementalRenderer<HTMLElement> = {
  createContainer: (layout) => document.createElement("div"),
  createWidget: ({ widget, value }) => {
    const el = document.createElement("div");
    el.dataset.widgetKind = widget.kind;
    el.textContent = String(value ?? "");
    return el;
  },
  appendChild: (parent, child) => parent.appendChild(child),
};

const controller = new AbortController();
const root = await traverseBlueprintAsync(blueprint.layout, stateMap, {
  renderer: domRenderer,
  signal: controller.signal,
});
document.body.appendChild(root);
#+end_src

Yielding is counter-based (deterministic, clock-free) and uses ~yieldControl~ from [[#scheduler][~@loom/scheduler~]] (a macrotask) by default. No production renderer ships against this yet — all current renderers are pull-model — so it is the validated BYOR extension point rather than a supported target.

** ~fiber~ — opt-in render capabilities

These capabilities leverage React's *own* fiber scheduler (they mark intent — priority, suspension, granular subscription); Loom does not add a second reconciler. All are *off by default*: when ~fiber~ is falsy the renderer takes the exact current code path (byte-identical output).

#+begin_src typescript
type FiberConfig = boolean | {
  granularUpdates?: boolean;   // each widget subscribes to its own binding path;
                               // only the changed widget re-renders (vs whole tree)
  suspense?: boolean;          // per-widget <React.Suspense> boundary so an async
                               // BYOC component can suspend without blanking siblings
  deferStreaming?: boolean;    // streaming widgets update via startTransition
};
// `true` enables all three.
#+end_src

~suspense~'s fallback is the widget placeholder or skeleton; ~deferStreaming~ applies to widgets of kind ~"StreamingText"~ or with ~props.defer === true~. Enabling any capability implies per-widget mounting (fiber mode), which inherently gives granular subscription.

#+begin_src typescript
// Turn everything on for one renderer:

// Or opt into individual capabilities:

  blueprint={bp}
  projectionRuntime={rt}
  executionId={id}
  fiber={{ granularUpdates: true, deferStreaming: true }}
/>
#+end_src

~fiber~ can also be set as a default on ~LoomProvider~ (~<LoomProvider fiber={…}>~); a ~BlueprintRenderer~ ~fiber~ prop overrides the provider default.

** ~useProjection~ hook

Subscribe to a single projection in any React component:

#+begin_src typescript

    executionId

The hook initialises from ~getState()~ and re-renders on every projection update.

** ~useDeferredProjection~ hook

Like ~useProjection~, but wraps streamed updates in ~startTransition~ so they are treated as *non-urgent*: urgent work (user input, eager-rendered projections) can interrupt a low-priority re-render mid-flight. The initial subscription read is still urgent.

#+begin_src typescript
import { useDeferredProjection } from "@loom/renderer-react";

  const stream = useDeferredProjection<StreamState>(projectionRuntime, "answer", executionId);
  return <pre>{stream.text}</pre>;
}
#+end_src

Use *only* for high-frequency, low-urgency projections (streaming text, live metrics); keep urgent projections (an approval result) on ~useProjection~ to avoid momentarily showing stale UI. Pairs well with ~InMemoryProjectionRuntime({ coalesceNotifications: true })~.

** ~useWidgetValue~ hook

Tear-free, *path-granular* selector for a single widget, built on ~useSyncExternalStore~. It subscribes to the widget's bound projection but re-renders only when the widget's own slice (~binding.path~) actually changes — so a projection update re-renders only the widgets whose values changed, not the whole blueprint. This is the subscription primitive behind ~fiber={{ granularUpdates: true }}~.

#+begin_src typescript
import { useWidgetValue } from "@loom/renderer-react";

function Cell({ widget, executionId }: { widget: Widget; executionId: string }) {
  const value = useWidgetValue<number>(projectionRuntime, widget, executionId);
  return <span>{value ?? "—"}</span>;
}
#+end_src

| Parameter     | Type                      | Description                                                     |
|---------------+---------------------------+-----------------------------------------------------------------|
| ~runtime~     | ~ProjectionRuntime~       | Projection state source                                         |
| ~widget~      | ~Widget~                  | Widget whose ~binding~ slice is selected                        |
| ~executionId~ | ~string~                  | Scopes projection state to this execution                       |
| ~isEqual~     | ~(a, b) => boolean~       | Optional equality for the resolved slice; defaults to ~Object.is~ |

** ~useDeferredWidgetValue~ hook

The ~startTransition~-based variant of ~useWidgetValue~ for high-frequency streaming widgets — path-granular, but subsequent updates are deferred so they never block urgent work. (~startTransition~ cannot be layered on ~useSyncExternalStore~, so this is a separate ~useState~-based implementation with its own ~Object.is~ slice guard.)

#+begin_src typescript

** ~AgentRunner~

#+begin_src typescript
interface AgentConfig {
  definition: AgentDefinition;   // from @loom/core, made via agent$()
  provider: LlmProvider;
  effectRuntime: EffectRuntime;
  maxIterations?: number;        // default 10
  systemPrompt?: string;
  parallelTools?: boolean | number;   // run a turn's tool calls concurrently (default false)
  skills?: SkillRegistry;             // progressively-disclosed expertise (optional)
  skillSelector?: SkillSelector;      // defaults to deterministicSkillSelector()
}

class AgentRunner {
  constructor(config: AgentConfig);
  run(input: AgentInput, ctx: EffectContext): Promise<AgentOutput>;
  asEffect(): LlmEffect<AgentInput, AgentOutput>;
}
#+end_src

During ~run~, the runner emits an ~AGENT_TOOL_CALL~ event (via ~ctx.emit~) for every tool it invokes and a single ~AGENT_COMPLETED~ event when the loop finishes. ~asEffect()~ returns the same behaviour wrapped as an ~LlmEffect~, ready to register on an ~EffectRuntime~.

*Parallel tool calls.* By default the runner executes a model turn's tool calls sequentially. Set ~parallelTools: true~ to run them all concurrently, or ~parallelTools: <n>~ to cap concurrency at ~n~ (via ~parallelLimit~ from [[#scheduler][~@loom/scheduler~]]). Regardless of setting, tool *results*, the emitted ~AGENT_TOOL_CALL~ events, and the messages fed back to the model are *always* in the model's tool-call order — so replay stays deterministic even though execution interleaves.

*Cancellation.* The runner calls ~throwIfAborted(ctx.signal)~ before each LLM round-trip and before each tool call, and forwards ~ctx.signal~ to ~provider.complete~ (as ~LlmRequest.signal~) and to ~parallelLimit~. So cancelling the owning execution (~ExecutionHandle.cancel()~) stops an agent loop promptly.

#+begin_src typescript
const runner = new AgentRunner({
  definition: InvestigatorAgent,
  provider: new AnthropicProvider(),
  effectRuntime,
  parallelTools: 4,   // up to 4 tool calls at once; results still in tool-call order
});
#+end_src

~AgentConfig~ also accepts an optional ~memory?: MemoryRuntime~. When the agent's ~definition.memoryId~ is set and a ~MemoryRuntime~ is supplied, ~run~ recalls prior entries into the prompt and writes the user prompt + assistant answer back afterward; ~AgentInput~ accepts ~memoryScope?: string~ (defaulting to ~ctx.executionId~) to scope recall per conversation. See [[#memory][~@loom/memory~]].

#+begin_src typescript
const runner = new AgentRunner({
  definition: InvestigatorAgent,
  provider: new AnthropicProvider(),
  effectRuntime,
  maxIterations: 8,
  systemPrompt: "You are an incident investigator.",
});

const result = await runner.run({ prompt: "Diagnose incident cpu-001" }, ctx);
// result: { content, toolCallLog: AgentStep[], iterations }
#+end_src

** Skills — ~SkillRegistry~ / ~SkillSelector~

When ~AgentConfig.skills~ is supplied, ~run~ selects the skills relevant to the turn *before* the loop, emits a ~SKILLS_SELECTED~ event, lazy-loads only those instruction bodies, appends them to the system prompt, and adds their tools to the model's menu (the agent's own tools win on id collision). Skills are defined with [[#builders][~skill$~]] and grouped in a registry.

#+begin_src typescript
const skills = new SkillRegistry()
  .register(CpuRunbook)
  .register(ReplicaLagRunbook);

const runner = new AgentRunner({
  definition: InvestigatorAgent,
  provider,
  effectRuntime,
  systemPrompt: "You are an SRE.",
  skills,                                   // selection is deterministic by default
  // skillSelector: llmSkillSelector(provider),  // opt-in model-driven selection
});
#+end_src

| Symbol | Purpose |
|--------+---------|
| ~SkillRegistry~ | Holds ~SkillDefinition~s; ~register~ / ~get~ / ~all~ / ~ids~ / ~find(query)~ (keyword scorer over id/name/description/tags) |
| ~SkillSelector~ | ~select(input, registry): Promise<string[]>~ — returns the relevant skill ids |
| ~deterministicSkillSelector(max?)~ | Default. Top-N by ~find()~ score — stable for the same input, so a replayed run reconstructs the same prompt |
| ~llmSkillSelector(provider, max?)~ | Opt-in. The model picks ids from the description menu. Same non-determinism as the ReAct loop; the ~SKILLS_SELECTED~ event is the audit/record hook |

*Replay note.* Because Loom re-executes the agent loop on replay and does not record the LLM's outputs, *which* skills load must be replay-stable — hence the deterministic default. The emitted ~SKILLS_SELECTED~ event records the choice for observability and a future record/replay path.

* ~@loom/a2ui~ — the Agent-to-UI protocol
:PROPERTIES:
:CUSTOM_ID: a2ui
:END:

A2UI (Agent-to-UI) is a first-class protocol for patch/event-based UI updates. Instead of the ad-hoc "emit a token, accumulate in a projection" pattern, an agent or flow drives a named *surface* by emitting declarative *patches*. A patch is a single addressed mutation; patches travel as ordinary ~A2UI_PATCH~ events through the normal event pipeline, so every UI update is durable, ordered, and replays deterministically. Import from ~@loom/a2ui~.

#+begin_src typescript
import {
  A2UI_PATCH, DEFAULT_SURFACE,
  applyA2UIPatch, applyA2UIPatches, getSurfaceValue,
  createA2UIEmitter, a2uiSurfaceProjection, A2UIRuntime,
  type A2UIPatch, type A2UIPatchPayload, type A2UISurfaceState, type A2UIEmitter,
} from "@loom/a2ui";
#+end_src

** Protocol constants

#+begin_src typescript
const A2UI_PATCH = "A2UI_PATCH";   // the single event type carrying UI updates
const DEFAULT_SURFACE = "ui";      // default surface id
#+end_src

All A2UI updates ride on a single event type, ~A2UI_PATCH~. A surface is just a keyed bag of state (~A2UISurfaceState = Record<string, unknown>~); the default surface id is ~"ui"~. Multiple surfaces can coexist under one execution by giving each a distinct id.

** ~A2UIPatch~ — the five ops

A patch is one declarative mutation, addressed by a dot-notation ~path~ (~""~ = the surface root).

#+begin_src typescript
type A2UIPatch =
  | { op: "set";       path: string; value: unknown }
  | { op: "merge";     path: string; value: Record<string, unknown> }
  | { op: "append";    path: string; value: unknown }
  | { op: "remove";    path: string }
  | { op: "increment"; path: string; by?: number };
#+end_src

| Op          | Fields             | Effect                                                        |
|-------------+--------------------+--------------------------------------------------------------|
| ~set~       | ~path, value~      | Replaces the value at ~path~                                  |
| ~merge~     | ~path, value~      | Shallow-merges an object into the object at ~path~           |
| ~append~    | ~path, value~      | Pushes ~value~ onto the array at ~path~ (tokens/logs/timelines) |
| ~remove~    | ~path~             | Deletes the key/entry at ~path~                              |
| ~increment~ | ~path, by?~        | Adds ~by~ to the number at ~path~; ~by~ defaults to ~1~      |

** ~A2UIPatchPayload~ & ~A2UISurfaceState~

#+begin_src typescript
interface A2UIPatchPayload {
  surface?: string;        // defaults to DEFAULT_SURFACE ("ui")
  patches: A2UIPatch[];    // applied in order, atomically per event
}

type A2UISurfaceState = Record<string, unknown>;
#+end_src

The payload of every ~A2UI_PATCH~ event is an ~A2UIPatchPayload~: the target ~surface~ plus the ordered list of ~patches~ to apply.

** Pure reducers

The reducers are pure and immutable — they never mutate the input state, so they are safe to use inside projections, tests, and time-travel tooling.

#+begin_src typescript
// Apply one patch, returning a new state
function applyA2UIPatch(state: A2UISurfaceState, patch: A2UIPatch): A2UISurfaceState;

// Fold a batch of patches left-to-right
function applyA2UIPatches(state: A2UISurfaceState, patches: readonly A2UIPatch[]): A2UISurfaceState;

// Resolve a dot-path (already split into parts) against a surface
function getSurfaceValue(state: A2UISurfaceState, parts: string[]): unknown;
#+end_src

#+begin_src typescript
let s: A2UISurfaceState = {};
s = applyA2UIPatch(s, { op: "set", path: "phase", value: "analyzing" });
s = applyA2UIPatches(s, [
  { op: "append", path: "log", value: "started" },
  { op: "increment", path: "progress", by: 25 },
]);
getSurfaceValue(s, ["progress"]);   // → 25
#+end_src

** ~createA2UIEmitter(emit, surface?)~ — the producer

Wraps any ~emit~ function into an ~A2UIEmitter~. Each method emits exactly one ~A2UI_PATCH~ event carrying a single-patch payload (except ~patch()~, which sends an arbitrary batch atomically as one event).

#+begin_src typescript
function createA2UIEmitter(
  emit: (eventType: string, payload: unknown) => void,
  surface?: string,   // defaults to "ui"
): A2UIEmitter;
#+end_src

Any context that can emit events — a flow's ~ctx~, a step's ~EffectContext~, an agent — can build one:

#+begin_src typescript
// Inside a step handler or effect (EffectContext has emit)
const ui = createA2UIEmitter((type, payload) => ctx.emit(type, payload));
ui.set("status", "working");
#+end_src

Inside a flow runner you do not need to build one — ~ctx.ui~ is already an ~A2UIEmitter~ bound to the ~"ui"~ surface (see [[#workflow-context][WorkflowContext]]).

| Method                      | Emits                                        | Description                                |
|-----------------------------+----------------------------------------------+--------------------------------------------|
| ~set(path, value)~          | one ~set~ patch                              | Replace the value at ~path~                |
| ~merge(path, value)~        | one ~merge~ patch                            | Shallow-merge an object at ~path~          |
| ~append(path, value)~       | one ~append~ patch                           | Push onto the array at ~path~              |
| ~remove(path)~              | one ~remove~ patch                           | Delete at ~path~                           |
| ~increment(path, by?)~      | one ~increment~ patch                        | Bump the number at ~path~ (~by~ default 1) |
| ~patch(patches)~            | one event with all ~patches~                 | Apply an arbitrary batch atomically        |

** ~a2uiSurfaceProjection(surfaceId?)~ — consumer 1 (projection bridge)

Returns a ~Projection<A2UISurfaceState>~ whose ~id~ equals ~surfaceId~ (default ~"ui"~) and which folds ~A2UI_PATCH~ events into surface state. Register it in an existing ~ProjectionRuntime~ and the A2UI surface becomes an ordinary projection — no other changes required.

#+begin_src typescript

#+end_src

Bind any widget to it with the ordinary ~DataBinding~ — the ~projectionId~ is the surface id, and ~path~ is a dot-path into the surface. ~BlueprintRenderer~ needs no changes:

#+end_src

** ~A2UIRuntime~ — consumer 2 (standalone surface store)

A framework-agnostic store for apps that do not have a ~ProjectionRuntime~. Feed it events and it maintains one surface state per ~(surface, executionId)~ pair; ignores any event whose type is not ~A2UI_PATCH~.

#+begin_src typescript
class A2UIRuntime {
  handleEvent(event: EventEnvelope): void;   // ignores non-A2UI_PATCH events
  getSurface(surface: string, executionId: string): A2UISurfaceState;
  seed(surface: string, executionId: string, state: A2UISurfaceState): void;
  subscribe(
    surface: string,
    executionId: string,
    handler: (state: A2UISurfaceState) => void,
  ): () => void;                             // returns an unsubscribe function
}
#+end_src

| Method        | Description                                                                  |
|---------------+------------------------------------------------------------------------------|
| ~handleEvent~ | Applies an ~A2UI_PATCH~ event to its surface; skips all other event types    |
| ~getSurface~  | Synchronous read of the current surface state (empty object if none yet)     |
| ~seed~        | Populates a surface directly (server-side restore) without processing events |
| ~subscribe~   | Registers a live listener; called after each matching event; returns unsubscribe |

#+begin_src typescript
const a2ui = new A2UIRuntime();

const runtime = new WorkflowRuntime({
  eventStore, snapshotStore, effectRuntime,
  onEvent: (event) => a2ui.handleEvent(event),

#+end_src

* ~@loom/scheduler~
:PROPERTIES:
:CUSTOM_ID: scheduler
:END:

An *ephemeral*, dependency-free cooperative scheduler for live in-flight async work. It applies Fiber principles — priority, interruption, incremental progress — to the *async agentic layer*, not to a UI reconciler. It governs three things and nothing else: the *order* queued work acquires a slot (by ~Priority~), *how many* tasks run at once, and *cancellation* via ~AbortSignal~. Import from ~@loom/scheduler~.

#+begin_src typescript
import {
  createScheduler, parallelLimit, yieldControl, Priority,
  throwIfAborted, linkSignals, withTimeout, signalReason, NEVER_SIGNAL,
  type Scheduler, type SchedulerEvent,
} from "@loom/scheduler";
#+end_src

It is deliberately *not durable*: Loom's event-sourcing + ~replay-vm~ already own durable pause/resume (~SuspendError~). The scheduler *complements* that layer for live work — do not persist scheduler state.

** ~Priority~

#+begin_src typescript
enum Priority {
  Immediate    = 0,   // must-run-now (a user-triggered cancel/approval)
  UserBlocking = 1,   // foreground work a user is waiting on (a live agent turn)
  Normal       = 2,   // default — ordinary flow/effect work
  Idle         = 3,   // background/pre-fetch that should yield to everything else (planning)
}
#+end_src

Priority is *ordering only* — lower numeric value = more urgent (dequeued first). Unlike React's scheduler these lanes do not drive a frame-deadline time-slicer (yielding to a frame budget is meaningless while awaiting a socket); they only decide the order queued tasks acquire a slot when running under a finite concurrency cap.

** ~createScheduler(config?)~

#+begin_src typescript
function createScheduler(config?: {
  concurrency?: number;                       // default Infinity — gating disabled
  onEvent?: (e: SchedulerEvent) => void;      // optional telemetry sink
}): Scheduler;

interface Scheduler {
  schedule<T>(
    task: (signal: AbortSignal) => Promise<T>,
    opts?: { priority?: Priority; signal?: AbortSignal; label?: string },
  ): Promise<T>;
  readonly inFlight: number;   // tasks currently executing
  readonly pending: number;    // tasks queued waiting for a slot
}
#+end_src

The default ~concurrency: Infinity~ *disables gating entirely*: ~schedule~ reduces to ~await task(signal)~ with no queue node, controller, or bookkeeping — *~zero overhead*. Overhead is only paid when a finite cap is explicitly set. Under a finite cap, queued tasks are ordered by ~(priority asc, enqueue order)~; a task's ~signal~ is honoured while it is still queued, so a cancel that arrives before it starts never occupies a slot.

~SchedulerEvent~ (delivered to ~onEvent~) is one of ~{ type: "scheduled" }~, ~{ type: "started" }~, or ~{ type: "settled"; ok: boolean }~, each carrying the task's ~priority~ and optional ~label~.

#+begin_src typescript
const scheduler = createScheduler({ concurrency: 3 });

// Fan several LLM calls through a shared cap; a live turn preempts background planning.
const [a, b] = await Promise.all([
  scheduler.schedule((signal) => provider.complete({ messages, signal }),
                     { priority: Priority.UserBlocking, label: "live-turn" }),
  scheduler.schedule((signal) => planner.compose(signal),
                     { priority: Priority.Idle, label: "prefetch-plan" }),
]);
#+end_src

** ~parallelLimit(tasks, opts?)~

Runs ~tasks~ with bounded concurrency, *preserving input order in the result array* — ~results[i]~ always corresponds to ~tasks[i]~ regardless of completion order. This ordering guarantee is load-bearing for Loom's replay determinism (it backs ~ctx.parallel~ and ~AgentRunner~'s ~parallelTools~).

#+begin_src typescript
function parallelLimit<T>(
  tasks: Array<(signal: AbortSignal) => Promise<T>>,
  opts?: { limit?: number; signal?: AbortSignal; failFast?: boolean },
): Promise<T[]>;
#+end_src

| Option     | Type          | Default     | Description                                                    |
|------------+---------------+-------------+----------------------------------------------------------------|
| ~limit~    | ~number~      | unbounded   | Max tasks running at once; ~≤ 0~ means unbounded               |
| ~signal~   | ~AbortSignal~ | none        | Caller cancellation, linked into each task's signal            |
| ~failFast~ | ~boolean~     | ~true~      | Abort siblings on the first rejection and reject with that error |

Degenerates to ~Promise.all~ semantics when ~limit >= tasks.length~. With ~failFast: false~, every task runs to settlement and the first error (by input order) is thrown after all complete.

#+begin_src typescript
const pages = await parallelLimit(
  urls.map((u) => (signal) => fetch(u, { signal }).then((r) => r.json())),
  { limit: 5 },
);
// pages[i] corresponds to urls[i]
#+end_src

** ~yieldControl()~

#+begin_src typescript
function yieldControl(): Promise<void>;
#+end_src

Yields the current task back to the host via a *macrotask* boundary (~setTimeout(…, 0)~, unref'd), so the event loop genuinely drains between chunks — higher-priority work (and, in a browser, paint/input) can run before continuing. Use in CPU-bound loops that want to stay responsive, e.g. an interruptible tree walk (~traverseBlueprintAsync~ uses it by default).

** AbortSignal utilities

Small, dependency-free helpers for cooperative cancellation. All are optional-signal-safe: passing ~undefined~ allocates nothing and is a no-op, so the non-cancellable fast path pays zero cost.

#+begin_src typescript
function throwIfAborted(signal?: AbortSignal): void;
function linkSignals(...signals: Array<AbortSignal | undefined>): AbortSignal | undefined;
function withTimeout(ms: number, parent?: AbortSignal): { signal: AbortSignal; dispose(): void };
function signalReason(signal: AbortSignal): unknown;
const NEVER_SIGNAL: AbortSignal;
#+end_src

| Helper            | Description                                                                                     |
|-------------------+-------------------------------------------------------------------------------------------------|
| ~throwIfAborted~  | Throws the signal's reason if it is already aborted; no-op when ~undefined~ or not aborted       |
| ~linkSignals~     | Combines several signals into one that aborts when any input does; ~undefined~ if none supplied, the same signal if exactly one (prefers native ~AbortSignal.any~) |
| ~withTimeout~     | Derives a signal that aborts after ~ms~ (a ~TimeoutError~) or when ~parent~ aborts; call ~dispose()~ when the work settles to release the timer/listener |
| ~signalReason~    | Normalises an aborted signal's ~reason~ into a throwable (defaults to an ~AbortError~)           |
| ~NEVER_SIGNAL~    | A single shared signal that never aborts — handed to a task when the caller supplied none, avoiding a per-call ~AbortController~ allocation |

#+begin_src typescript
const { signal, dispose } = withTimeout(5_000, ctx.signal);   // 5s budget, honours the parent
try {
  return await provider.complete({ messages, signal });
} finally {
  dispose();
}
#+end_src

* Complete Example
:PROPERTIES:
:CUSTOM_ID: complete-example
:END:

A minimal agentic application: a flow that fetches data, waits for human approval, then applies a fix.

#+begin_src typescript
import {
  flow$, step$, handler$, projection$,
  WorkflowRuntime,
  EffectRuntime,
  type FlowRunner,
} from "@loom/sdk";
import { SqliteEventStore } from "@loom/event-runtime";
import { SqliteSnapshotStore } from "@loom/snapshot-runtime";
import { InMemoryProjectionRuntime } from "@loom/projection-runtime";
import {
  blueprint$, grid, MetricCard, ApprovalCard,
} from "@loom/blueprint-runtime";
import { z } from "zod";

// ── 1. Define steps with co-located handlers ──────────────────────────────────
// handler$ auto-registers LazyEffect via registerFlow — no manual effectRuntime.register needed

const AnalyzeStep = step$({
  id: "analyze",
  inputSchema: z.object({ ticketId: z.string() }),
  outputSchema: z.object({ severity: z.number(), summary: z.string() }),
  handler: handler$(async (input) => ({
    severity: 4,
    summary: `High CPU spike detected for ticket ${input.ticketId}`,
  })),
});

// No handler$ for suspension steps — ctx.suspend() in runner handles it
const ApprovalStep = step$({
  id: "approval-gate",
  inputSchema: z.object({ ticketId: z.string() }),
  outputSchema: z.unknown(),
});

const FixStep = step$({
  id: "apply-fix",
  inputSchema: z.object({ ticketId: z.string() }),
  outputSchema: z.object({ applied: z.boolean() }),
  handler: handler$(async (_input) => ({ applied: true })),
  retry: { maxAttempts: 2, backoffMs: 1000 },
});

// ── 2. Define flow ────────────────────────────────────────────────────────────

const TicketFlow = flow$({
  id: "ticket-resolution",
  name: "Ticket Resolution",
  version: "1.0.0",
  inputSchema: z.object({ ticketId: z.string() }),
  outputSchema: z.object({ resolved: z.boolean() }),
  steps: [AnalyzeStep, ApprovalStep, FixStep],
});

// ── 3. Write the runner ───────────────────────────────────────────────────────

const ticketRunner: FlowRunner<{ ticketId: string }, { resolved: boolean }> = async (ctx, input) => {
  ctx.emit("TICKET_STARTED", { ticketId: input.ticketId });

  const analysis = await ctx.run(AnalyzeStep, { ticketId: input.ticketId });
  ctx.emit("ANALYSIS_COMPLETE", analysis);

  if (analysis.severity >= 3) {
    ctx.emit("APPROVAL_REQUIRED", { ticketId: input.ticketId, ...analysis });
    // Suspend until a "TicketApproved" event arrives via runtime.resume()
    await ctx.suspend({ on: "TicketApproved", correlationKey: input.ticketId });
  }

  const result = await ctx.run(FixStep, { ticketId: input.ticketId });
  ctx.emit("TICKET_RESOLVED", { ticketId: input.ticketId });

  return { resolved: result.applied };
};

const RegisteredTicketFlow = { definition: TicketFlow, runner: ticketRunner };

// ── 4. Wire up projections ───────────────────────────────────────────────────

const TicketProjection = projection$({
  id: "ticket",
  name: "Ticket State",
  initialState: { severity: null as number | null, awaitingApproval: false },
  handlers: {
    ANALYSIS_COMPLETE: (state, event) => ({
      ...state,
      severity: (event.payload as { severity: number }).severity,
    }),
    APPROVAL_REQUIRED: (state) => ({ ...state, awaitingApproval: true }),
    TICKET_RESOLVED: (state) => ({ ...state, awaitingApproval: false }),
  },
});

// ── 5. Define blueprint ───────────────────────────────────────────────────────

const TicketBlueprint = blueprint$({
  id: "ticket-dashboard",
  title: "Ticket Resolution",
  layout: grid({
    columns: 2,
    gap: 16,
    children: [
      MetricCard({
        title: "Severity",
        binding: { projectionId: "ticket", path: "severity" },
      }),
      ApprovalCard({
        title: "Approve Fix",
        binding: { projectionId: "ticket", path: "awaitingApproval" },
        approveLabel: "Apply Fix",
      }),
    ],
  }),
  projections: ["ticket"],
});

// ── 6. Bootstrap runtime ──────────────────────────────────────────────────────

const effectRuntime = new EffectRuntime();
const projectionRuntime = new InMemoryProjectionRuntime();
projectionRuntime.register(TicketProjection);

const runtime = new WorkflowRuntime({
  eventStore: new SqliteEventStore("./data/events.db"),
  snapshotStore: new SqliteSnapshotStore("./data/snapshots.db"),
  effectRuntime,
  onEvent: (event) => projectionRuntime.handleEvent(event),
});

// registerFlow auto-wires LazyEffect for AnalyzeStep and FixStep (both have handler$)
runtime.registerFlow(RegisteredTicketFlow.definition, RegisteredTicketFlow.runner);

// ── 7. Start and interact ─────────────────────────────────────────────────────

const handle = await runtime.start(RegisteredTicketFlow, { ticketId: "TICK-001" });

handle.waitForSuspend().then(async () => {
  console.log("Workflow suspended — awaiting approval");

  setTimeout(async () => {
    const resumeHandle = await runtime.resume(handle.executionId, {
      eventType: "TicketApproved",
      payload: { approvedBy: "ops-team" },
    });
    resumeHandle.waitForCompletion().then(() => {
      console.log("Ticket resolved");
    });
  }, 2000);
});
#+end_src
