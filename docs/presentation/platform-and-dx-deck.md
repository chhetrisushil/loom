### From primitives to a platform: how you build, test, run, and ship a Loom app today

**defineConfig · the `loom` CLI · pluggable compute · testing · evals & deploy-sim · orchestration**

## The core is done. This is the platform around it.

The durable event log, deterministic replay, and suspend/resume are the foundation.
On top of that, Loom is now a **platform**:

```
   authoring        →   defineConfig   →   the loom CLI   →   compute
   step$/flow$          one composition       logs·debug        in-proc →
   agent$/tool$         root, no boilerplate   eval·deploy       HTTP →
                                               gen·inspect       Cloud Run
```

Plus **testing**, **evals**, and **deploy-simulation** — all lenses on the same log.

**One canonical example** wires all of it: `loom-starter` (in the sibling [`loom-examples`](../examples.md) repo).

---

## Before: hand-wired composition root

Every app repeated ~35 lines of the same wiring:

```ts
const eventStore = new InMemoryEventStore();
const snapshotStore = new InMemorySnapshotStore();
const effectRuntime = new EffectRuntime();
const projectionRuntime = new InMemoryProjectionRuntime();
projectionRuntime.register(agentSurfaceProjection("mission"));
const runtime = new WorkflowRuntime({
  eventStore, snapshotStore, effectRuntime,
  onEvent: (e) => projectionRuntime.handleEvent(e),
});
runtime.registerFlow(flow.definition, flow.runner);
// …bus, agents, capabilities, retries…
```

---

## After: `defineConfig`

```ts
const app = defineConfig({
  storage: { kind: "sqlite", dir: ".loom", branching: true },
  surfaces: ["mission", "telemetry"],
  flowModules,                          // from `loom gen` (folder convention)
  effectMiddleware: [retryMiddleware({ maxRetries: 3 })],
  agents, capabilityAgents,             // A2A routing
  validate: "warn",                     // static flow-graph checks at boot
});
// → { runtime, effectRuntime, projectionRuntime, bus, stores, close }
```

**Sugar, not a cage.** It returns the same primitives you'd hand-build — drop a
level any time. Empty middleware ⇒ byte-identical to before. *(ADR 0006)*

## Effect middleware

Cross-cutting concerns as a composable chain — the HTTP-middleware model, applied
to effects (tool / LLM / human / A2A):

```ts
effectMiddleware: [
  retryMiddleware({ maxRetries: 3, baseDelayMs: 200, factor: 2, jitter: true }),
  loggingMiddleware,
]
// (ctx, input, next) => Promise  — wraps every effect
```

- Retries use **deterministic** FNV-1a jitter (no `Math.random`) — replay-safe.
- **Never** retries a suspension or an aborted signal.
- Write your own for logging, idempotency, tracing. *(ADR 0006)*

## Folder convention → build-time codegen

The Next.js instinct, done the replay-safe way — **static** generation, not runtime
globbing:

```
app/flows/release-approval/flow.ts     ← you write this
app/loom.gen.ts                        ← `loom gen` writes this
```

```ts
// AUTO-GENERATED by `loom gen`
import * as _f0 from "./flows/release-approval/flow";
export const flowModules = [_f0];      // → defineConfig({ flowModules })
```

`loom new flow <name>` scaffolds; `loom gen` regenerates. The flow set is fixed at
build time ⇒ identical on every resume and remote worker. *(ADR 0011)*

## The `loom` CLI — the log, from your terminal

```
loom logs   --db <db> <id>            tail the event timeline
loom debug  --db <db> <id> --at N     time-travel: state at sequence N
loom inspect --db <db> <id>           web timeline + slider
loom eval   --dir evals/              replay goldens vs expectations (CI gate)
loom deploy check --logs L --config C simulate deploy vs new flow defs
loom check  --manifest <path>         static flow-graph checks
loom gen / loom new                   folder-convention codegen
```

Every command is a **pure function over the log** behind a thin bin — a fold at a
chosen sequence *is* time-travel. *(ADRs 0010, 0012, 0014)*

## Testing — deterministic, offline

```ts
import { createTestApp, waitForPhase, captureGolden } from "@loom/testing";

const app = createTestApp({ surfaces: ["mission"], flows: [myFlow] });
const h = await app.runtime.start(myFlow, input);
await h.waitForSuspend();
await waitForPhase(app.projectionRuntime, "mission", h.executionId, "awaiting-approval");
await app.runtime.resume(h.executionId, { eventType: "ApprovalGranted", payload: { approved: true } });
```

- `createTestApp` = `defineConfig` defaulted to in-memory.
- `waitFor`/`waitForPhase` replace hand-rolled `for (i<200) sleep(25)` loops.
- **VCR** LLM provider: record once, replay deterministically — no live calls. *(ADR 0009)*

## Evals & deploy-sim — the log IS the fixture

**Evals.** Capture an execution's log as a golden, pair it with expectations, and
replay it in CI:

```jsonc
{ "name": "happy path", "log": [ /* EventEnvelope[] */ ],
  "expect": { "status": "completed", "stepsCompleted": ["assess", "apply"] } }
```

**Deploy simulation.** Replay historical logs against your **new** flow definitions
before promoting — a removed step or missing flow is flagged *breaking*. Catches
resume-incompatibility that type-checking can't. *(ADR 0008)*

```
loom deploy check --logs prod-logs/ --config dist/app.js   →  ✓ safe to promote
```

## Run anywhere — the compute seam

```
defineConfig({ dispatcher })
   └─ ExecutionDispatcher ─┬─ local     (in-process)
                           ├─ remote    (HTTP → stateless worker-server)
                           └─ Cloud Run (platform-cloudrun)
```

An **ExecutionPackage** carries resume coordinates (identity + sequence) — **never
code**. Workers ship their own bundle and resolve flows **by id** from a static
registry. Stateless workers recover from crashes by folding shared stores.

Distributed fan-out: `graph-executor` runs graph nodes as **per-node executions**
(one writer each), joined via lineage. *(ADRs 0001–0005)*

---

## Orchestration primitives

The recurring route → plan → dispatch → gate loop, as composable functions — not a
base class:

```ts
import { decideApproval } from "@loom/orchestrator";

await decideApproval(
  { goal, riskLevel: "medium" },
  { onAutoApprove: () => log("low risk — auto"),
    onManualRequired: () => surfacePendingApproval(),
    waitForManual: () => new Promise((r) => { resolver = r; }) }
);
```

Proven by migrating a real example's approval gate; kept only where it fit
(composition over inheritance). *(ADR 0013)*

## Performance — tuned on the hot paths

The fold runs on every commit, resume, and projection. It got faster without a
single API change:

| Change | Win |
| --- | --- |
| Copy-on-write fold (share untouched frames) | **~7.7×** on wide flows |
| Periodic snapshots (`snapshotEvery`) | bounded recovery replay |
| Bulk `copyPrefix` on fork (SQL, no JS re-serialize) | no fork blow-up |
| `buildTrace` O(N²) → O(N) | **~60×** for the inspector |

Correctness pinned by tests for each invariant. Public SDK untouched. *(ADR 0015)*

## Put it together — `examples/loom-starter`

One compact release-approval app that exercises **all** of the above:

```bash
pnpm --filter @loom/loom-starter gen      # folder convention → loom.gen.ts
pnpm --filter @loom/loom-starter start    # start → pause at gate → resume → release
pnpm --filter @loom/loom-starter test     # @loom/testing (incl. retry proof)
pnpm --filter @loom/loom-starter eval     # golden replay
pnpm --filter @loom/loom-starter deploy:check
```

`defineConfig` + `loom gen` + `retryMiddleware` + `@loom/testing` + evals +
deploy-sim + the compute seam — in one small, readable package.
